# 공개 패키지 점검 기록

이 기록은 공개 `guide/` 폴더의 자료 구성·문서 연결을 점검한 것이다. 개인·기업 시스템의 설치·인증·자동화·운영 결과를 기록한 문서가 아니다.

## 공개 범위

- 진입 안내·기능 정의·구축 절차·도구별 안내·기존 빈 기록 양식 3개·가상 시험·공식 참고자료를 포함한다.
- 개인 원문·비공개 자료의 위치 목록·실제 계정과 인증 정보·채워진 운영 기록·가이드 소유자의 배포 환경 기록은 포함하지 않는다.
- 해당 개인 자료 없이도 질문·설계·구축·검증 절차를 이해하고 진행할 수 있다. 선택한 제품의 설치 자원·계정·인증은 별도로 필요하다.

## 콘텐츠·이메일·연결 대상의 설정 안내

초기 셋업과 작업별 분기에서 콘텐츠 수집·지식 재사용, 이메일 연결·로컬 앱, 그 밖의 연결 대상별 설정 가이드로 이어진다. 선택한 서비스만 공식 설정·권한·실제 실행 환경에 맞춰 구성하고, 사용자가 해야 할 로그인·2FA·관리자 조치의 화면·행동·완료 확인 방법을 안내한다. 앱 설치나 로그인만으로 완료 처리하지 않고 실제 수신·조회·반영·재조회·중단/복귀를 검증하도록 명세했다. 콘텐츠 자동화는 수집 대화와 분리한 새 대화의 근거 검색까지 확인한다.

## 능동 운영과 다섯 실행기의 확인 범위

사용자가 먼저 질문하지 않아도 정한 예약/이벤트로 관찰·제안·허용 실행·결과 재조회·수정·다음 점검이 이어지도록 지침·셋업·양식·수용 기준을 연결했다. OmO·OpenClaw·Hermes·Codex·Claude는 공식 기능과 실제 실행 경로를 대조하며, 내장 기능이 부족하면 필요한 외부 기동·상태·발신 역할을 구성한다. 모든 제품을 한꺼번에 설치하거나 고유 세션 DB를 공유하는 설계가 아니다.

문서 검토·로컬 CLI help·가상 사례·실제 운영을 구분한다. 현재 다섯 런타임의 실제 예약/이벤트·모델·외부 알림·복구 시험을 실행한 것은 아니다. 제품별 확인 근거와 미검증은 [실행기 독립 운영 검증](<../20_도구별/실행기 독립 운영 검증.md>)에 기록한다. 선택한 실제 실행기의 P01–P06 증거가 없으면 능동 운영 준비 완료로 표시하지 않는다.

## Jev·Reason Network와 최종 인계 누락 방지

두 제품의 역할·도입 필요성·기존 대안을 보여 주는 안내를 추가하고 README·셋업·결정/진행/검증 기록을 연결했다. 기존 검증 양식에 최종 체크리스트와 최종 구축 보고서를 추가해 두 제품의 도입/미도입/보류·근거·대안·실제 구현/검증 상태가 나타나도록 했다. 검토는 필수이고 설치는 선택이다. 보류가 필수 기능에 영향을 주면 해당 범위는 미완료로 유지한다.

S18에는 누락·근거 있는 미도입·의존 기능 보류·도입 후 미검증의 가상 표본을 추가했다. 정의와 문서 간 연결을 검사한 것이며 제품 실행 결과가 아니다. Jev·Reason 공식 근거를 재확인했지만 실제 API 호출·Reason 설치/통신은 수행하지 않았다.

## 기존 모델 분류 프롬프트 대안

2026-10-29 사용자 제안 원문을 [분류 전용 프롬프트와 검증](<../10_구축/분류 전용 프롬프트와 검증.md>)에 보존하고 입력/6키 JSON·후보/근거·불확실성·실제 권한 차단·비교/복귀 절차를 추가했다. 코드·기존 모델을 먼저 검토하고 필요·권한·예산이 정해진 경우에만 Jev를 같은 표본으로 비교한다. 추가 API 도입과 기존 모델의 사용 비용/한도를 구분한다.

기존 세 양식의 분류 방식·버전·입력/출력 계약·V20 근거·비용/한도·최종 보고 항목을 연결했다. Jev 미도입으로 선택한 대체 분류 기능의 검증까지 제외하지 않는다. 마스터 지침에는 작업별 안내 링크를 두고 전문은 분류 작업에서 읽도록 했다. S16의 분류 가상 표본과 JSON 예시는 입력/기대 결과 정의이며 실제 모델의 정확도·보안·비용 시험 결과가 아니다.

## 에이전트 선택과 Hermes 예시

2026-10-29 Hermes를 선택형 적용 예시로 명시하고, OpenClaw·Codex·Claude·OmO 등 기존 또는 필요한 에이전트를 선택하도록 README·공통 지침·셋업·기능 정의·백엔드·도구별 안내·기존 결정 양식의 문구를 맞췄다. 목록 밖의 실행기도 공통 운영 계약과 실제 지원 경로로 검토한다. 제품별 명령·설정과 과거 확인 근거는 보존하며 다른 제품의 즉시 호환이나 기능 동등성을 보장하지 않는다. 에이전트 설치·교체·실행 시험을 수행한 변경은 아니다.

## Google 계정 연결·설정 대리 수행

2026-10-29 Google Calendar·Gmail·선택 Google 서비스의 기존 커넥터 재사용과 직접 OAuth 경로를 구분하고, 에이전트가 할 설정·사용자 로그인/동의·관리자 조치·실제 운영 호스트의 검증·실패 재개를 구체화했다. 업무별 허용 행동과 기술 scope/ACL을 구분하고, 메일 발신·일정 초대/통지를 연결 동의만으로 허용하지 않는다. 선택한 기능만 검증하며 기존 세 양식의 결정→진행/행동 카드→실증/최종 보고에 연결했다.

S18의 Google 진행 표본 6개는 인증 분리·사용자 조치 대기·초안 전용·일정 부수효과·응답 유실·OFF/재인증의 입력과 기대 결과다. 공식 문서와 구조를 확인한 것이며 실제 계정 조회·설치·OAuth 동의·API·발신·초대·토큰 회수·운영 시험은 수행하지 않았다.

## ZIP만 받은 상태의 시작 점검

공개 ZIP을 별도 임시 폴더에 풀고 기존 대화·비공개 볼트 없이 README → AGENTS → 셋업 절차와 기록 양식으로 진행할 수 있는지 문서상 대조했다. 로컬 CLI와 기존 파일 재사용, 휴대폰만 사용하며 집 실행기가 꺼진 경우, 회사 자료를 외부로 내보낼 수 없는 경우 모두 필요한 분기·대기·저장·재개 안내를 확인했다. ZIP의 38개 자료는 매니페스트의 크기·SHA-256과 일치했고 누락·중복·경로 탈출·해결되지 않는 내부 파일 링크가 없었다. 기본 설계 방향은 각 사용자의 실제 선택·승인과 구분한다.

## 검증하지 않은 범위

가상 시험은 입력과 기대 결과만 제공하며 아직 실행하지 않았다. 제품 설치·사용자 인증·실제 서비스 연결·모델 실행·모바일 접속·권한 집행·백업 복구·부하·비용 집행은 이 공개 패키지 검사에 포함하지 않았다. 실제 대상에서는 [초기 셋업 흐름](<../10_구축/초기 셋업 흐름.md>)에 따라 필요한 범위를 구현하고 [검증·운영 기록](<../30_양식/검증·운영 기록.md>)에 관찰 증거를 남긴다.
