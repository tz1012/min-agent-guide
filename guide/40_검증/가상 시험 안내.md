# 가상 시험 안내

[가상 시험 사례.json](<가상 시험 사례.json>)은 실제 계정·자료 없이 사용할 수 있는 입력과 기대 결과다. 테스트 실행기나 실행 결과가 아니라, 선택한 구현에 연결할 검증 계약이다. 모든 내용은 가상이며 외부 전송 권한을 부여하지 않는다.

## 적용 방법

1. [초기 셋업 흐름](<../10_구축/초기 셋업 흐름.md>)으로 선택한 기능과 아래 적용 조건을 대조한다. 사례별 `적용 / 제외·사유`를 먼저 기록한다. 시험을 위해 새 운영 API·DB·다중 작업자를 구현하지 않는다.
2. 적용 사례는 JSON의 `sandboxPolicy`에 따라 제공 자료 읽기·로컬 초안·로컬 상태 기록 범위에서 수행한다. 기존 실행기의 파일·세션·로그를 재사용할 수 있다. 외부 동작을 직접 구현하는 경우에만 필요한 시험용 어댑터를 사용한다.
3. S07–S18 중 적용하는 가상 이벤트·권한·쿼터·상태 전이만 로컬에서 재현한다. 기존 제품 내부를 재현할 수 없으면 문서 검토로 범위를 기록하고 허용된 실제 제품 시험으로 확인할 계획을 남긴다. 문서 검토를 실행 통과로 기록하지 않는다.
4. 적용하는 기본 사례부터 실행하고 해당 `expected`를 모두 확인한다. 기존 기능으로 충족하는 역할도 실제 결과·기록을 확인한다. 결과의 정확한 문구보다 근거·상태·부작용·중복 여부를 검사한다.
5. S03을 적용하면 S01을 먼저 수행한 같은 저장 상태에서 동일 키로 다시 요청한다. S06을 적용하면 시험용 상태/기존 재개 기능으로 부분 완료 뒤 재시작을 확인한다. 사례 입력의 가상 필드명을 실제 제품 스키마로 강제하지 않는다.
6. 실제 입력·결과 ID·저장 위치·실행 로그·검사 방법·확인자·일시를 [검증·운영 기록](<../30_양식/검증·운영 기록.md>)에 남긴다. 실패한 사례의 재시험도 별도로 기록한다.

| --- | --- | --- |

S13–S18은 [업무 시나리오·셋업 질문](<../10_구축/업무 시나리오·셋업 질문.md>)에서 채택한 부분만 적용한다. 복수·전체 선택한 시나리오는 모두 검증 범위에 두고 첫 단계 이후의 시험은 대기로 남긴다. JSON의 후보·목표·일정 ID와 상태는 가상 계약이므로 새 제품·저장소나 동일한 스키마를 요구하지 않는다. 순서가 있는 이벤트는 각 단계 직후의 상태를 확인한다. 예를 들어 S13의 최종 완료만 확인하면 알림 직후 잘못 완료한 오류를 놓칠 수 있다.

S16의 `automationSamples`, S18의 `emailSamples`는 선택 기능에 맞춘 추가 가상 표본이다. 실제 연결의 [K01–K08](<../10_구축/콘텐츠 수집·지식 재사용.md>)·[E01–E08](<../10_구축/이메일 연결과 로컬 앱.md>)·[C01–C06](<../10_구축/연결 대상별 설정 가이드.md>)에 대응한다. fixture의 정책값은 예시이며 사용자 설정으로 복사하지 않는다.

## 분류 전용 프롬프트의 가상 표본

S16의 `classificationSamples`는 [분류 전용 프롬프트와 검증](<../10_구축/분류 전용 프롬프트와 검증.md>)을 위한 **사람이 작성한 입력·기대 결과 정의 8개**다. 해당 판단 기능을 채택하면 Jev 미도입 여부와 관계없이 검증한다. 새 모델·서비스 설치나 유료 호출을 요구하지 않는다. 기존 모델을 실제로 호출하는 경우에도 정한 권한·비용 한도를 먼저 적용한다.

| 표본 ID | 정의한 상황과 기대 경계 |
| --- | --- |
| classification-normal | 명확한 요청·제공 프로젝트 후보·실제 근거 위치를 가진 정상 판단 후보 |
| classification-ambiguous | 부분 자료·후속 상태 불명·복수 후보 충돌은 uncertain/null과 검토 사유로 보류 |
| classification-unknown-candidate | JSON에 정상적으로 담긴 ID라도 입력 후보 목록 밖이면 거부 |
| classification-injection | 자료 속 역할 변경·정답 강요·외부 전송 지시를 따르지 않고 검토 표시 |
| classification-false-completion | 알림 읽음·일정 종료·메일 발송을 근거로 후속 불필요를 판단한 응답은 의미 검증에서 거부 |
| classification-invalid-json | 잘린 JSON을 반영하지 않고 제한된 복구 또는 검토 대기로 처리 |
| classification-no-execution-authority | 외부 행동 요청은 분류 후보로만 반환하며 쓰기·발송·완료 변경 권한을 얻지 않음 |
| classification-unrelated-null | 명확히 무관한 자료는 근거 있는 null을 정상 결과로 허용 |

각 표본의 `input`은 가이드의 `material_types`, `project_candidates`, `policy`, `sources` 계약을 따른다. `referenceOutput`은 여섯 키로 작성한 사람의 기대 출력이며 실제 모델 반환값이 아니다. `suppliedResponse`는 수신 검증기의 거부 경계를 확인하기 위한 가상 원시 응답이다. 정상 예시뿐 아니라 후보 밖 ID·근거 의미 오류·의도적으로 잘린 JSON도 포함한다. `expectedValidation`은 **예상 판정**이며 실제 시험 성적이 아니다. `not_evaluated`는 앞 단계에서 거부해 다음 검사를 수행하지 않는 기대 경로를 뜻한다.

- JSON 파싱·키/타입/허용값·source_id와 행 범위 검사를 근거 의미 검증과 분리한다. 존재하는 행을 붙였더라도 그 행이 판단을 뒷받침하지 않으면 거부한다. 기대 출력의 문구 복사 여부보다 필드별 판단·근거·검토 여부를 비교한다.
- `candidate_only`도 판단 후보일 뿐 자동 쓰기·발송·완료 처리 허가가 아니다. `review_pending`에는 정상적으로 보류된 후보와 거부된 응답이 모두 포함되므로 실패 이유를 함께 남긴다. 명확히 무관한 null과 근거 부족으로 미결정인 null을 구분한다.
- `classification-no-execution-authority`의 선언만으로 도구 차단을 검증한 것은 아니다. 선택한 실제 분류 호출에 실행 도구·쓰기 자격증명이 없거나 정책상 차단되는지 별도 확인한다. 이 가상 시험을 위해 실제 외부 발송을 시도하지 않는다.
- S16의 지식 수집·검색은 기존 V24에, 이 분류 비교·대안 평가는 **기존 V20**에 연결한다. 적용되는 권한·주입·비용 항목은 V03/V09/V19에 함께 기록한다. 표본 ID는 fixture 내부 식별자이며 새 최상위 검증 번호가 아니다.

현재 수행한 JSON 파싱·표본 구조 일관성 확인은 자료 정의 점검이다. 모델 정확도·프롬프트 방어·의미 검증기·권한 집행·운영 성능의 실행 통과를 뜻하지 않으며, 8개 표본의 실제 실행 상태는 모두 미실행으로 유지한다.

## 능동 운영과 실행기별 동일 시험

S13의 `proactiveSamples`는 P01–P06에 대응하며 새 사용자 메시지가 없는 시작, 하루의 변화, 수정·재검사, 중복·OFF·시간대·한도·사용자 제어를 제공한다. S18의 `runtimeHandoffSample`은 실행기를 바꿔도 작업 정본·권한·소유권·미완료 단계가 유지되는 계약이다. 모든 값은 가상이며 실제 제품 명령·서비스 호출은 실행하지 않는다.

[능동 운영과 완료 추적](<../10_구축/능동 운영과 완료 추적.md>)과 [실행기 독립 운영 검증](<../20_도구별/실행기 독립 운영 검증.md>)에 따라 동일 표본을 실제 선택한 제품/에디션/버전에서 재현한다. 공식 문서로 경로를 확인한 것, CLI help를 읽은 것, 가상 입력을 검토한 것, 실제 예약으로 실행한 것을 각각 기록한다. 프롬프트에 수동 입력해 답변을 받는 시험은 대화 종료 후의 선제 기동을 대신하지 않는다. 다섯 제품 이름이 fixture에 있다고 다섯 런타임을 실행한 것은 아니다.

## 실제 연결 검증으로 넘어갈 때

가상 사례 통과는 실제 서비스 인증·권한·전달·복구 성공의 증거가 아니다. 선택한 연결마다 비민감 시험 계정/자료와 명시된 허용 범위를 사용해 실제 입출력·조회 확인·실패·재시도를 검증한다. 기능 정의 8절의 개인/엔터프라이즈 사례와 연결별 계약을 추가한다.

S07–S12는 API·이벤트 계약 검증용이다. 실제 모바일 UI, 집 장비 전원·네트워크, Cloudflare·Google 계정, 조직 보안 경계의 검증을 대신하지 않는다. 해당 실제 시험은 V15–V20에 기록한다.

S13–S18의 텍스트·상태 시험도 실제 캘린더 쓰기·알림 전달·자동 배포·녹음·음성 인식·기업 권한 집행의 증거가 아니다. 채택한 실제 제품의 UI/API 지원 차이, 비민감 음성 표본의 인식/화자/타임코드 품질, 권한 회수·삭제 전파와 시나리오 간 경계를 V21–V26에서 별도로 확인한다. 현재 계정에 없는 기능은 지원된다고 가정하지 않는다.

현재 사례는 모두 미실행이다. 담당 에이전트가 결과를 생성하지 않은 상태에서 통과로 바꾸지 않는다. 적용 제외는 성공이 아니며, 기능 추가 시 해당 사례를 다시 선택한다.

## 선택 구성 검토와 최종 보고서의 가상 누락 점검

S18의 `optionalComponentsReviewSamples`는 Jev·Reason Network 누락, 근거 있는 미도입, 의존 기능이 있는 보류, 도입 후 미검증을 다룬다. 두 행이 최종 체크리스트와 구축 보고서에 나타나고 결정·실제 구현·시험 상태가 일치하는지 대조한다. 미도입 제품 설치나 유료 호출 없이 문서로 확인할 수 있다. 아래 자료는 입력·기대 결과 정의이며 제품 런타임 시험 결과가 아니다.
