# 저비용 서비스 확인 사항

**확인일: 2026-10-28.** 금액은 공식 페이지의 USD 표시이며 세금·환율·계약 할인은 반영하지 않았다. 아래는 공개 문서 확인 결과다. 계정 개설, 결제, OAuth 연결, 배포와 초과 한도 시험은 수행하지 않았다. 문서의 갱신일과 이번 확인일은 다르며, 가입·운영 전 선택한 계정의 실제 플랜·쿼터를 다시 확인한다.

이 파일에 판단에 필요한 핵심 내용을 포함했다. 외부 링크는 근거와 변경 확인용이다. 모든 서비스를 한꺼번에 도입하는 제안은 아니다. 선택 결과와 비용 상한은 [구축 결정·규칙 기록](<../30_양식/구축 결정·규칙 기록.md>)에 기록한다.

## 1. 서비스 역할과 무료 범위

| 서비스 | 이 시스템에서의 후보 역할 | 확인한 무료 범위 | 한도 초과·유료 전환 시 판단 |
| --- | --- | --- | --- |
| Workers Free | 경량 HTTP API, 웹훅 접수·인증·라우팅 | 계정 일 100,000 요청, 호출당 CPU 10ms, 메모리 128MB | 일 요청 한도 초과는 1027 오류. 라우트가 fail-open이면 Worker를 우회할 수 있으므로 인증을 맡긴 경로는 fail-closed를 확인한다. CPU 초과도 실행 실패 요인이다. |
| Pages Free | 정적 화면·문서 사이트 | Functions를 호출하지 않는 정적 요청 무료·무제한. 월 500 빌드, 동시 1빌드, 빌드 20분, 20,000파일, 파일당 25MiB | Functions는 Workers의 일 요청 한도를 공유한다. 빌드·파일 상한을 넘는 배포는 무료 범위로 계획하지 않는다. 월 빌드 상한 도달 시 UI·재시도 동작은 이번에 실측하지 않았다. |
| Tunnel | 로컬·서버의 백엔드에 외부 연결 경로 제공 | 계정당 1,000 터널 포함 | 한도에 도달하면 새 터널 생성이 실패하고 기존 터널은 계속 작동한다. 추가 용량 구매는 터널당 월 $4.50. 실행할 원본 서버·전원·회선·도메인은 별도다. |
| Access / Zero Trust Free | 화면·관리 API의 사용자 접근 제어 | Free 플랜 사용자 50명 한도 | 50명 초과 운영은 유료 플랜 검토 대상. 가격표의 Pay-as-you-go는 $7/사용자/월. 51번째 이후 사용자만 과금된다고 가정하지 않고 좌석·청구 조건을 확인한다. 한도 초과 로그인 동작은 이번 조사에서 확정하지 않았다. |
| D1 / Workers Free | 클라우드 SQL 상태·작업 기록 저장 후보 | 일 읽기 5,000,000행·쓰기 100,000행, 계정 총 5GB. Free는 DB당 500MB, 계정 10개 DB | 일 읽기·쓰기 한도 도달 시 쿼리가 오류로 중단된다. 저장 한도 도달 시 신규 데이터·스키마 작업이 제한된다. Free는 초과 자동 과금으로 계속되는 모델이 아니다. |
| R2 Standard | 첨부·원본 파일·백업 객체 저장 후보 | 월 10GB-month, Class A 1,000,000회, Class B 10,000,000회, 인터넷 egress 비용 없음 | 무료 포함량 초과는 종량 과금: 저장 $0.015/GB-month, A $4.50/백만 회, B $0.36/백만 회. Standard에만 무료량 적용; Infrequent Access는 별도 과금이다. |

- Workers: [가격](https://developers.cloudflare.com/workers/platform/pricing/)(문서 갱신 2026-10-02), [한도·초과 동작](https://developers.cloudflare.com/workers/platform/limits/)(2026-10-12). Paid Standard는 월 $5 구독을 바탕으로 월 1,000만 요청·3,000만 CPU ms 포함 후 요청 $0.30/백만 회, CPU $0.02/백만 ms 추가. 요청 수만으로 전체 비용을 계산하지 않는다.
- Pages: [한도](https://developers.cloudflare.com/pages/platform/limits/)(2026-09-05), [정적 자산·Functions 요금](https://developers.cloudflare.com/pages/functions/pricing/)(2026-09-08).
- Tunnel: [용량·과금·초과 동작](https://developers.cloudflare.com/tunnel/features/tunnels-for-platforms/)(2026-10-16), [설치 전제](https://developers.cloudflare.com/tunnel/get-started/)(2026-09-30). 공개 호스트 이름을 사용하는 설정은 Cloudflare의 도메인과 `cloudflared`가 실행되는 서버를 요구한다.
- Access: [공식 요금표](https://www.cloudflare.com/plans/zero-trust-services/), [50명 한도가 표시된 공식 지역 페이지](https://www.cloudflare.com/id-id/plans/zero-trust-services/). Free의 지원·보존·보안 기능 범위를 유료 전체 기능과 동일하게 취급하지 않는다.
- D1: [가격·초과 동작](https://developers.cloudflare.com/d1/platform/pricing/)(2026-04-21), [용량·복구 한도](https://developers.cloudflare.com/d1/platform/limits/)(2026-10-24). Paid는 월 250억 읽기행·5,000만 쓰기행·5GB 포함 후 읽기 $0.001/백만 행, 쓰기 $1/백만 행, 저장 $0.75/GB-month 추가. 행 수는 API 요청 수와 다르고 인덱스도 저장·쓰기량에 영향을 준다.
- R2: [가격](https://developers.cloudflare.com/r2/pricing/)(2026-10-26), [가입·월별 청구](https://developers.cloudflare.com/r2/get-started/). R2 구독 활성화가 필요하며 무료량은 지출 상한이 아니다. 사용량은 청구 단위로 올림된다. egress가 무료여도 저장·요청·앞단 Worker 비용까지 모두 무료라는 뜻은 아니다.

## 2. 연결·보안·로그의 별도 조건

- Tunnel과 Access를 구분한다. Tunnel은 연결 경로이며, 공개 애플리케이션을 만들었다고 로그인 제한까지 자동 설정되는 것은 아니다. Access 정책을 사용한 보호는 별도로 구성하고 승인되지 않은 사용자·직접 원본 주소·다른 호스트 경로에서 우회되지 않는지 시험한다. [공식 공개 애플리케이션 안내](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/)
- Quick Tunnel은 개발·시험용이다. 임시 호스트명, 가용성 보장 없음, 동시 진행 요청 200개 제한과 초과 429 응답, SSE 미지원 조건이 있다. 운영 주소나 장기 웹훅 수신 주소로 채택하지 않는 것을 기본 제안으로 둔다. [공식 Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)
- 보존 기간은 로그 종류별로 다르다. **Zero Trust Free의 Access·DNS·Network·HTTP 로그는 24시간**, 관리 로그는 18개월이다. 장기 감사 자료가 필요하면 필요한 이벤트·별도 저장 방식·내보내기 가능 플랜을 결정한다. 모든 로그 내보내기가 Free에 포함된다고 가정하지 않는다. [공식 로그 보존표](https://developers.cloudflare.com/cloudflare-one/insights/logs/)(2026-10-15)
- Workers Logs는 확인일 기준 Free 일 200,000이벤트·3일 보존이다. 공식 문서는 **2026-12-01부터 Observability 요금 적용 예정**이라고 안내한다. 이 수치를 장기 고정 비용으로 쓰지 않는다. [Workers Logs 가격과 변경 안내](https://developers.cloudflare.com/workers/platform/pricing/#workers-logs)
- D1 Free의 Time Travel 복구 기간은 7일이다. 별도 보존·내보내기·복원 시험의 필요성은 업무 복구 목표로 결정한다. 로그 보존과 데이터 백업은 구분한다. [D1 한도](https://developers.cloudflare.com/d1/platform/limits/)
- 비용 알림과 실제 차단을 구분한다. 허용 사용자, 호출·동시 실행·재시도 횟수, 업로드 크기, 저장 보존량, LLM 호출 예산을 애플리케이션에서 제한하고 초과 시 대기·중단·승격 중 어떤 동작을 할지 정한다.

## 3. Google Docs와 Drive API의 비용·쿼터

Google Docs의 본문 읽기·수정과 Drive의 파일 검색·메타데이터·변경 목록은 서로 다른 API다. 연결 계약과 사용량도 나누어 기록한다.

| API | 확인일의 표준 사용 요금·한도 | 초과·변경 사항 |
| --- | --- | --- |
| Docs API | 표준 사용은 추가 비용 없음. 분당 읽기 프로젝트 3,000회·사용자/프로젝트 300회, 쓰기 프로젝트 600회·사용자/프로젝트 60회 | 한도 초과는 일반적으로 429와 재시도 대상. 공식 가격 항목에 2026년 후반 기준 초과 과금 도입 예정이 명시돼 있다. 현재 공개된 문서만으로 초과 단가·개시일을 확정하지 않는다. |
| Drive API | 표준 사용은 추가 비용 없음. 새 기준은 분당 프로젝트 1,000,000 quota units·사용자/프로젝트 325,000 units. 일 프로젝트 egress 기준 1TB, 일 사용량 과금 기준 400,000,000 units | 2026-05-01 이후 새 프로젝트 대상 쿼터 체계. 과거 사용 프로젝트는 기존 쿼터가 유지될 수 있다. 초과 응답은 403 또는 429. 공식 문서는 향후 기준 초과 과금과 최소 90일 전 공지를 예고하며 상세 요금은 후속 안내 대상으로 둔다. |

- [Docs 한도·가격](https://developers.google.com/workspace/docs/api/limits)(문서 갱신 2026-09-03), [Drive 한도·가격](https://developers.google.com/workspace/drive/api/guides/limits)(2026-09-11), [Workspace API 변경 정책](https://developers.google.com/workspace/tools-safety)(2026-09-03)을 확인했다. 현재 표준 무료 범위와 미래 과금 예고를 구분한다. 실제 프로젝트의 콘솔 쿼터가 우선 확인 대상이다.
- Drive의 quota units는 요청 개수가 아니다. 예를 들어 `files.get` 5, `files.list` 100, `files.update` 50 units로 작업마다 다르다. 일 사용량·egress는 별도 계측한다. [Drive 한도](https://developers.google.com/workspace/drive/api/guides/limits)
- API 추가 사용료와 Google 계정·Workspace 구독·Drive 저장 용량·실행 호스트·LLM 요금은 별개다. 문서 API가 표준 범위에서 무료라는 이유로 전체 시스템 운영비를 0원으로 기록하지 않는다.
- 403/429에는 지수 백오프와 무작위 지연, 최대 횟수·최종 실패 상태를 둔다. 권한 거부와 사용량 제한을 구분하고, 처리 결과가 불명확한 쓰기를 무조건 반복하지 않는다.

## 4. Google Docs 최소 권한과 수정 충돌

- 필요한 파일만 다룬다면 **`https://www.googleapis.com/auth/drive.file`**를 우선 검토한다. 앱이 만들었거나 사용자가 앱에서 선택·공유한 파일에 접근하며 Docs API도 지원한다. 기존 문서는 Google Picker 등으로 파일별 선택 권한을 받는 흐름을 정한다. 파일 ID를 알고 있다는 사실만으로 접근이 허용되지는 않는다. [Docs scopes](https://developers.google.com/workspace/docs/api/auth), [Drive scopes와 Picker](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)
- `documents.readonly`는 읽기 전용이지만 사용자의 전체 Docs 범위이고, `documents`는 전체 Docs 수정 범위다. 전체 Drive의 `drive`·`drive.readonly`는 restricted 범위다. 읽기/쓰기 여부와 대상 파일 범위 두 축으로 최소 권한을 판단하고 공개 앱의 검증 요건을 확인한다. [Docs scopes](https://developers.google.com/workspace/docs/api/auth)
- 개인 시스템은 본인 OAuth 계정·대상 파일·토큰 저장 위치를 정한다. 엔터프라이즈는 허용 앱·실행 주체·공유 드라이브·퇴사 및 권한 철회 절차를 추가한다. 액세스·리프레시 토큰은 공개 화면이나 문서에 저장하지 않고 실행 환경의 보호된 비밀 저장소에 둔다.
- 동시 수정 기본 제안은 `documents.get`으로 읽기 → `revisionId` 기록 → `documents.batchUpdate`에 `writeControl.requiredRevisionId` 전달이다. 최신 리비전과 다르면 400 오류로 쓰기가 거부되므로 재읽기 후 변경안을 다시 계산한다. [공식 WriteControl](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents/batchUpdate#writecontrol)
- 공동 편집과의 자동 병합을 의도한 작업만 `targetRevisionId`를 검토한다. 너무 오래된 리비전은 거부될 수 있다. 리비전 조건을 생략한 쓰기를 기본 동기화 방식으로 채택하지 않는다. [공식 수정 지침](https://developers.google.com/workspace/docs/api/how-tos/best-practices)
- 문서에 여러 탭이 있으면 읽기 시 `includeTabsContent=true`, 수정 시 대상 탭 ID를 고려한다. 첫 탭만 읽은 결과를 문서 전체로 취급하지 않는다. [공식 탭 처리 지침](https://developers.google.com/workspace/docs/api/how-tos/best-practices)

## 5. 변경 감지와 로컬 위키 동기화

- 작은 시스템의 첫 제안은 사용자가 선택한 문서에 대한 **명시적 가져오기 또는 제한된 주기 조회**다. 변경 지연이 허용되는지 확인한 후 웹훅이 필요한 경우에만 추가한다. 이는 구축 복잡도를 줄이기 위한 설계 제안이다.
- Drive 변경 피드를 사용하면 `changes.getStartPageToken`으로 시작 위치를 얻고 `changes.list`를 순회한다. 다음 페이지는 `nextPageToken`, 마지막 페이지 이후 재개 위치는 `newStartPageToken`이다. 해당 변경을 로컬에 기록한 뒤 재개 위치를 저장해 재시작 후 빠뜨리지 않도록 한다. [공식 변경 조회](https://developers.google.com/workspace/drive/api/guides/manage-changes)
- `files.watch` 또는 `changes.watch` 알림은 변경 신호이며 **본문·메타데이터·폴더 경로를 담지 않는다**. 알림 후 Drive 변경 목록과 Docs 본문을 권한 있는 API로 다시 읽는다. `files` 채널 최대 1일, `changes` 최대 1주, 만료 미지정 시 기본 1시간이며 자동 갱신되지 않는다. 만료 전 새 채널 생성과 중첩 기간의 중복 처리가 필요하다. [공식 Push 알림](https://developers.google.com/workspace/drive/api/guides/push)
- 웹훅 수신에는 유효한 HTTPS 주소가 필요하다. 채널 ID·리소스 ID·별도 채널 토큰을 확인하고, 알림의 문서 ID를 그대로 신뢰해 임의 자원을 처리하지 않는다. 사용자 로그인 화면을 요구하는 Access 보호와 Google의 기계 호출은 별도 경로로 설계하고 시험한다. 채널 토큰에 OAuth 토큰을 넣지 않는다. [공식 Push 요구사항](https://developers.google.com/workspace/drive/api/guides/push)
- **동기화 계약 제안:** 원본 권위(Google Docs/로컬 Markdown), 단방향 또는 양방향, 문서·탭과 로컬 파일의 매핑, 마지막 리비전·내용 해시, 생성/수정/삭제/권한 철회 처리, 충돌 담당자, 마지막 성공·오류를 기록한다. 양방향을 선택하면 사람의 수정과 에이전트 수정이 반복 전파되지 않도록 작업 ID·출처·적용 버전을 관리한다.
- **동기화 검증 제안:** 같은 알림 중복, 채널 만료, 장기 오프라인, 수정 중 재수정, 문서 삭제·접근 철회, API 429, 토큰 만료 후 재인증을 가상 자료로 시험한다. 웹훅만으로 복구를 판단하지 말고 주기적 변경 조회와 현재 상태 비교로 보완한다.

## 6. 최소 비용안을 확정할 질문

- 상시 켜진 기존 장치에서 SQLite·위키를 운영할 것인가, 별도 호스팅이 필요한가?
- 외부 접근이 필요한 화면·API·웹훅은 무엇인가? 로컬 전용으로 충분한 기능은 무엇인가?
- Google Docs는 입력 원본, 협업 편집 화면, 결과 전달 중 어떤 역할이며 누가 수정하는가?
- 허용 지연·사용자 수·일 작업 수·저장량·로그 및 백업 보존 기간은 얼마인가?
- 무료 한도에 가까워지면 작업 중단, 실행 빈도 축소, 사용자 확인 후 유료 전환 중 무엇을 할 것인가?
- LLM·도메인·호스트·저장·API 각각의 월 상한과 운영 책임자는 누구인가?

공식 문서로 확인한 범위와 설계 제안을 구분해 기록했다. 이 자료는 연결·성능·보안·복구 시험의 완료 기록이 아니다.
