# 일정·할 일 도구 확인 사항

**Google Calendar의 화면으로 일정과 할 일을 함께 관리하는 방식은 초기 후보가 될 수 있다.** 별도 Google Tasks 앱을 설치할 필요와, Tasks 데이터·API를 사용하는지는 다른 결정이다. 먼저 필요한 업무와 자동화 범위를 정한 후 제품·연결 방식을 선택한다. 이 문서는 2026-10-28 공식 문서를 확인한 기록이며 제품 도입, 계정 연결, 실제 서비스 시험은 수행하지 않았다.

## 1. Calendar 안의 ‘일정’과 ‘할 일’

| 구분 | 실제 역할 | 구축 시 해석 |
|---|---|---|
| Calendar 일정(Event) | 약속·회의·시간 확보와 참석자 관리 | 시작·종료 시간이 지나도 실제 업무 완료로 판정하지 않는다. |
| Calendar 화면의 할 일(Task) | 해야 할 일과 완료 상태, 날짜·시간 배치 | Tasks 목록과 연결되는 항목이다. 별도 Tasks 앱을 열지 않고 Calendar에서 다룰 수 있다. |
| 독립 Google Tasks 앱 | 같은 Tasks 업무를 다루는 별도 사용자 접점 | 앱 추가 설치를 필수로 삼지 않는다. 사용하는 접점의 기능 차이는 확인한다. |
| 에이전트 실행 작업 | 조회·분석·도구 실행·재시도 과정 | 사용자의 할 일 ID와 에이전트 실행 ID를 연결하되 같은 상태로 합치지 않는다. |

Google은 Tasks를 개인 할 일 목록으로 설명하고 Gmail·Calendar 연동 및 기기 간 동기화를 제공한다. 따라서 사용자가 “Calendar 안에서만 쓰고 싶다”고 답하면 그 접점을 유지하고, 백엔드 연결이 필요할 때 Tasks 지원 여부를 별도로 조사한다. [Google Workspace의 Tasks 안내](https://support.google.com/a/users/answer/9296558?hl=en)

현재 컴퓨터용 Calendar 도움말에는 할 일의 시작·종료 시간, 별도 Deadline, 완료 처리, 반복 설정이 있다. 반복 할 일에는 종료 시간을 추가할 수 없으며, 방해 금지·회의 자동 거절은 직장·학교 계정으로 제한된다. **예정 시간, 마감, 완료는 각각 다른 값**으로 다룬다. [Calendar에서 할 일 만들기·관리](https://support.google.com/calendar/answer/9901136?hl=en)

할 일 시간 확보 기능은 2025-11-17 공식 발표에서 개인 계정·Workspace 등으로 제공한다고 안내했다. 계정 종류·앱·실제 배포 상태에 따른 사용 가능 여부는 구축 시 대상 화면에서 확인한다. [Google의 시간 확보 기능 발표](https://workspaceupdates.googleblog.com/2025/11/block-time-for-tasks-google-calendar.html)

## 2. 사용자 화면과 API 지원을 구분한다

| 필요한 동작 | 2026-10-28 공식 문서에서 확인한 범위 | 설계에 주는 제약 |
|---|---|---|
| 일정의 시간·반복·참석자 관리 | Calendar Events API가 제공 | 선택한 커넥터가 해당 필드와 변경 작업을 노출하는지 추가 확인한다. |
| 할 일 제목·메모·상태·목록 관리 | Tasks API가 제공 | Calendar 이벤트 연결만 있다고 Tasks 연결이 된 것은 아니다. |
| 할 일 완료 처리 | Tasks의 `status`와 `completed` | 시스템 상태 변경 성공과 실제 완료 근거를 각각 기록한다. |
| 할 일 예정 날짜 | Tasks의 `due` | **일 단위 예정 날짜이며 Deadline이 아니다.** 시각을 읽거나 쓸 수 없다. |
| Calendar 할 일의 시작·종료·Deadline·반복 전체 자동화 | 확인한 Tasks REST 리소스에 대응 필드가 없음 | UI 기능과 API의 동등 지원을 약속하지 않는다. 실제 연결 수단의 제공 범위로 좁힌다. |
| 팀 담당 할 일 생성 | Docs·Chat Spaces에서 배정하는 경로가 있음 | Tasks 공개 API의 `insert`로 배정 업무를 만들 수 있다고 가정하지 않는다. |

Tasks 리소스 문서는 **2026-10-19 개정 본문**에서 `due`를 Calendar 배치·수행 예정 날짜로 설명하며, Deadline과 다르다고 명시한다. 과거 문서·검색 요약의 “마감일” 표현만 따라 필드를 연결하면 안 된다. `status`는 `needsAction` 또는 `completed`이며, 완료 시각 필드가 별도로 있다. [Google Tasks REST 리소스](https://developers.google.com/workspace/tasks/reference/rest/v1/tasks)

Calendar 이벤트의 `status`는 일정의 확정·잠정·취소 상태다. 업무의 완료 여부가 아니다. 확인한 Events API의 유형 목록과 리소스에는 Tasks 완료 상태가 없으므로, 이벤트 조회 성공으로 할 일 조회까지 성공했다고 표시하지 않는다. [Google Calendar Events API](https://developers.google.com/workspace/calendar/api/v3/reference/events)

Docs·Chat Spaces에서 배정한 업무는 Tasks 공개 API로 신규 배정할 수 없다. 배정 원본에서 생성해야 한다. [Tasks 생성 API의 제한](https://developers.google.com/workspace/tasks/reference/rest/v1/tasks/insert)

### 연결 구현 시 빠뜨리기 쉬운 조회 조건

- Google의 웹·모바일 화면에서 완료한 항목을 API로 재확인할 때 `showCompleted=true`와 `showHidden=true` 조건을 확인한다.
- 배정받은 업무를 포함하려면 `showAssigned`, 삭제 추적에는 `showDeleted`, 목록 누락 방지에는 페이지 처리를 확인한다. 필요한 범위만 사용한다.
- 조회에 없다는 이유만으로 완료·삭제를 추정하지 않는다. 필터·권한·동기화 오류를 구분한다. [Tasks 목록 API](https://developers.google.com/workspace/tasks/reference/rest/v1/tasks/list)

## 3. 필요에 따라 선택하는 구성

아래는 이 패키지의 **설계 제안**이다. 제품 도입 목록이 아니며, 선택한 경로만 결정 기록과 설치 명세로 넘긴다.

| 확인된 사용자 필요 | 우선 검토할 구성 | 다른 구성으로 넘어갈 조건 |
|---|---|---|
| 개인: Calendar에서 직접 일정·할 일을 관리하고 에이전트는 정리·제안 | Calendar 화면 유지, 목표·프로젝트 맥락은 기존 노트, 지원되는 범위의 조회 | 실제 연결 도구가 할 일을 읽지 못하면 수동 전달·내보내기 또는 별도 Tasks 연결 선택 |
| 개인: 에이전트가 시간 배치·완료 확인까지 자동 처리 | 업무 상태는 Tasks 또는 기존 업무 도구, 시간 확보는 지원되는 Calendar 기능 | 필요한 시간·마감·반복 필드를 API로 다룰 수 없으면 아래 대안 중 하나를 선택 |
| 개인: 외부 할 일 서비스를 쓰지 않음 | 기존 Markdown 업무 목록을 원본으로 쓰고 필요할 때 Calendar 일정과 연결 | 여러 기기 동시 수정·공동 담당 등 현재 저장 방식의 부족이 확인될 때 확장 |
| 기업: Google 협업 안에서 단순 담당 배정 | 기존 Chat Spaces·Docs 배정 흐름과 개인 Calendar 표시 | 세부 권한·결재·상태 전이·감사·복잡한 의존 관계를 충족하지 못하면 기존 기업 업무 시스템 검토 |
| 기업: 이미 업무 관리 시스템이 있음 | 해당 시스템을 업무 상태·담당자 원본으로, Calendar는 시간·회의 접점으로 사용 | 기존 시스템이 요구를 충족하지 못할 때만 다른 제품·별도 백엔드 비교 |

Google Chat Space의 그룹 업무는 담당자에게 배정되고 개인 Tasks에도 나타난다. 생성·수정 알림이 Space에 표시되는 점과 관리자의 기능 설정을 확인한다. Calendar의 공유 설정만으로 같은 팀 업무 흐름이 생기는 것은 아니다. [Google의 Space 업무 안내](https://support.google.com/a/users/answer/13647384?hl=en)

기존 기업 도구를 검토하는 예로, Linear는 업무의 사람 담당자와 에이전트 위임을 구분하고 비공개 팀 접근 조건을 둔다. 이런 역할 구분을 요구사항으로 삼을 수 있지만 Linear 도입을 뜻하지는 않는다. 실제 제품의 요금제·관리 기능·데이터 경계·API는 선택 시 다시 확인한다. [Linear 담당·위임 모델](https://linear.app/docs/assigning-issues)

### Calendar 할 일 API가 부족할 때 선택할 대안

1. 사용자가 Calendar UI에서 시간·반복을 관리하고 에이전트는 지원되는 조회·제안·완료 확인만 수행한다.
2. API가 지원하는 Calendar 이벤트로 작업 시간을 확보하고, 할 일의 완료 상태는 Tasks·기존 업무 도구에 둔다. 이벤트와 업무 ID를 연결하고 이벤트 종료를 완료로 바꾸지 않는다.
3. 시간·마감·반복·담당·상태를 필요한 수준으로 자동화할 수 있는 다른 업무 도구를 비교한다. 기존 자료 이전 비용과 무료 범위까지 포함해 판단한다.

대안 2에서도 Calendar 할 일 시간 확보와 별도 이벤트를 동시에 중복 생성하지 않는다. 같은 업무를 여러 시간에 나눠 배치할 수는 있으며, 각 시간 블록은 하나의 업무 원본을 참조한다. 새로운 데이터베이스가 반드시 필요한 것은 아니다. 기존 업무 설명·노트·구성 기록으로 관계를 보존할 수 있으면 그것부터 사용한다.

## 4. 선택한 연결의 계약과 검증

- 연결 계약

	- 업무 원본, 계정·목록·업무 ID, Calendar ID·이벤트 ID, 목표·프로젝트 참조, 예정 시간·시간대·마감, 완료 기준과 실제 근거 위치를 정한다. 적용되지 않는 필드는 제외한다.
	- 변경 방향과 소유자를 정한다. 일정 이동은 시간 배치 변경이며 업무 완료가 아니다. 할 일 삭제·취소·완료를 별도 처리하고, 반복 업무는 해당 회차와 전체 규칙을 구분한다.
	- 메모·설명·마감 필드를 제품 필드에 임의로 덮어쓰지 않는다. 지원하지 않는 값은 기존 노트에 보존하거나 수동 처리로 표시한다.
	- 일정 공유는 업무 열람·수정 권한과 따로 확인한다. 시간 범위가 있는 할 일은 공개 범위를 정할 수 있고, Calendar의 강한 편집 권한을 가진 사람이 비공개 세부 내용을 볼 수 있는 경우도 있다. [일정·할 일 공개 범위](https://support.google.com/calendar/answer/34580)

- 실제 연결을 선택한 뒤의 확인

	- 가상 입력으로 이벤트 시간 종료, 알림 발송, 실제 할 일 완료가 각각 다른 상태로 남는지 확인한다.
	- 허용된 시험 항목으로 Calendar 화면의 완료 변경을 연결 도구가 다시 읽는지, 미지원 시간·마감 값이 손실되지 않는지 확인한다.
	- 같은 변경을 재시도해도 중복 업무·알림·시간 블록이 생기지 않아야 한다. 조회 오류나 완료 상태 확인 실패는 미확인으로 남긴다.
	- 기업의 배정 업무는 원본 삭제 영향까지 확인한다. Tasks에서 배정 업무를 삭제하면 Docs·Chat의 원본 업무도 삭제될 수 있으므로, 개인 보기에서 숨김·배정 해제·원본 삭제를 같은 작업으로 취급하지 않는다. [Tasks 배정·삭제 필드](https://developers.google.com/workspace/tasks/reference/rest/v1/tasks)

선택과 실제 도구 지원 범위는 [구축 결정·규칙 기록](<../30_양식/구축 결정·규칙 기록.md>), 확인 증거는 [검증·운영 기록](<../30_양식/검증·운영 기록.md>)에 남긴다. 서버 전원과 기기 전환 조건은 [백엔드 설계](<../10_구축/백엔드·기기 연속성·비용 설계.md>)를 따른다.
