# 셋업 진행 기록

이 파일은 **미착수 양식**이다. 문서를 작성한 것만으로 설치·인증·사용자 승인·검증이 완료되지 않는다. [초기 셋업 흐름](<../10_구축/초기 셋업 흐름.md>)을 따라 필요한 항목만 채운다.

D01–D09·권한·비용·연결 계약은 [구축 결정·규칙 기록](<구축 결정·규칙 기록.md>)이 정본이다. 이 파일은 진행 포인터·설치 계획·수동 조치만 관리하며, 실제 명령 결과·런타임 증거·검증된 운영 절차는 [검증·운영 기록](<검증·운영 기록.md>)에 남긴다. 같은 결정·증거를 복사하지 않고 해당 ID나 절을 연결한다.

재개 시 실제 대상 호스트·파일·서비스 상태를 마지막 증거와 대조한다. 완료 단계를 무조건 재실행하지 않고, 동일한 유효 승인도 반복 요청하지 않는다. 변경된 대상·내용·권한·비용만 다시 판단한다. 무응답은 승인이나 수동 조치 완료가 아니다.

## 문답 진행과 재개

[대화형 설계·운영 점검](<../10_구축/대화형 설계·운영 점검.md>)을 따라 사례→이유·성공 기준→예외→구조 요약의 순서로 필요한 질문만 이어간다. 답변·가정·막는 미정·후속 미정과 전체 구조 청사진은 [구축 결정·규칙 기록](<구축 결정·규칙 기록.md>)에 두고 이 파일에는 다음 질문과 진행 위치만 남긴다.

- 운영 점검은 최근의 실제 사례와 기존 설계·증거부터 대조한다. 사용자 체감과 관찰 결과는 [검증·운영 기록](<검증·운영 기록.md>)에 연결하고, 이미 운영 중인 설치 단계를 처음부터 반복하지 않는다.
- 청사진의 내용 확인과 실제 변경 권한을 구분한다. 현재 수행 범위에 포함되고 필요한 결정이 확정된 작업만 진행하며, 가정이나 질문 미응답을 확정·승인으로 바꾸지 않는다.
- 질문을 중단하거나 다음 회차로 넘길 때에는 현재 작업을 막는 질문과 후속 단계에서 답할 질문을 구분해 해당 결정 ID에 연결한다. 질문이 없는 독립 작업은 기존 허용 범위 안에서 계속한다.

## 필요 확인에서 제품 선택으로 넘어가는 조건

[업무 시나리오·셋업 질문](<../10_구축/업무 시나리오·셋업 질문.md>)에 따라 개인 지식관리·개인 라이프 관리·기업 업무 중 **필요한 흐름을 복수 또는 전체 선택**한다. 지원 범위와 첫 구축 순서는 별개다. 대화 보관·전사 기능도 여러 흐름이 함께 사용할 수 있다. 선택·우선순위·이유는 [구축 결정·규칙 기록](<구축 결정·규칙 기록.md>)에만 기록한다. 공통 환경 설정·확정 답은 재사용하고 개인·조직의 계정·자료·권한·결정 담당은 나눈다.

- 현재 단계의 질문을 1–3개씩 제시하고 이미 확정한 답·승인을 재사용한다. 제외한 기능의 상세 질문·설치·검증은 건너뛴다.
- 설계 채택은 제품 도입 승인이 아니다. 기존 기능으로 충족하면 그대로 사용하고, 부족한 기능이 확인될 때 제품·플랜·권한·비용을 비교한다.
- 첫 단계의 연결·완료 기준·권한·저장 위치가 결정되면 필요한 설치로 진행한다. 선택한 후순위 시나리오는 구축 대기 목록에 유지하고 다음 착수 조건을 남긴다. 단계 구축을 범위 제외로 바꾸지 않는다.
- 대화 기능을 선택하면 [대화 수집·전사·지식화](<../10_구축/대화 수집·전사·지식화.md>)의 수집 범위·참여자 고지/동의 기준·접근·보존·외부 처리 조건을 확정한 뒤 실제 자료를 받는다.

## 첫 사용 안내 인계 포인터

선택 접점에서 사용자가 시작·요청·결과 열기·중단·재개하는 실제 안내는 [검증·운영 기록](<검증·운영 기록.md>)의 “첫 사용 안내”에 작성한다. 서버가 꺼졌을 때 가능한 일·접수 미확인 표시, 실패 알림·재인증·도움 요청 방법을 포함한다. 안내 위치·인수자·수행 확인 증거: **미정 / 미정 / 미검증**.
