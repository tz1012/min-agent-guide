# 검증·운영 기록

이 파일은 앞으로 채울 양식이다. 아래 사례는 시험 계획이며, 실제 설치·실행·검증이 완료됐다는 기록이 아니다. [기능 정의](<../최소한의 에이전트 시스템 구축 - 기능 정의.md>), [구축·운영 절차](<../10_구축/구축·운영 절차.md>), [구축 결정·규칙 기록](<구축 결정·규칙 기록.md>)의 확정값을 기준으로 작성한다.

## 검증 계획과 판정

대표 입력과 기대 결과를 실제 업무 기준으로 채운 후 실행한다. 상태는 `미검증 / 통과 / 실패 / 제외`로 기록하고, 제외는 사유와 판단 담당을 남긴다.

각 사례의 적용 범위를 F/D 결정과 연결한다. 기기 전환·Docs/Sheets 연결·다중 작업자·추가 모델·별도 감사 체계는 선택된 범위에서만 시험한다. 제품 내장 기능은 실제 로그·상태 조회·결과로 확인할 수 있으며 자체 시험용 API나 저장소를 요구하지 않는다. 비용 확인·한도는 첫 유료 모델 호출 등 첫 비용 발생 전부터 적용한다.

[업무 시나리오·셋업 질문](<../10_구축/업무 시나리오·셋업 질문.md>)에서 채택한 개인 지식관리·개인 라이프 관리·기업 업무를 대표 흐름으로 적용한다. 복수·전체 선택이면 모든 선택 흐름과 연결을 검증 범위에 두고 단계별 실행 순서를 기록한다. V21–V26는 해당 설계를 선택한 경우만 추가하며 제품 도입의 조건으로 일괄 강제하지 않는다. 실제 업무의 작은 표본으로 기대 결과를 먼저 고정하고, 변경 전후 같은 표본을 비교한다.

### 선택한 콘텐츠 자동화·이메일·기타 연결의 실제 시험

K/E/C는 아래 문서의 하위 시험 항목이며 새로운 전역 검증 번호가 아니다. 기존 V01–V26의 해당 증거에 연결한다. 모든 결과는 현재 **미검증**이며 선택한 범위만 시험한다.

| 적용 범위 | 시험 계약 | 기록할 증거 |
| --- | --- | --- |
| 지식 수집·재사용 자동화 | [K01–K08](<../10_구축/콘텐츠 수집·지식 재사용.md>) — 실제 입력부터 위키·목록/이력·검색 갱신, 새 대화 재검색, 중복·교정·권한·부분 실패·서버 OFF; V01–V10/V12/V15/V16/V18/V22/V24–V26 | 입력/출처/작업 ID, 실제 트리거·규칙·호스트, 변경 파일/버전, 검색 호출·기대/실제 근거, 실패 후 재개·중복 없음 |

위키 폴더 생성, 앱 설치, 로그인 완료, 수동 수집 성공만으로 자동화 완료를 표시하지 않는다. 테스트를 위해 실제 메일 발송·공유·삭제를 자동 허용하지 않는다. 실제 서비스 시험을 못 하면 문서/가상 검토 결과와 남은 실제 시험을 구분한다.

### 능동 운영·실행기 독립 검증

## 대화형 운영 점검 — 점검 회차마다 작성

[대화형 설계·운영 점검](<../10_구축/대화형 설계·운영 점검.md>)에 따라 기대 설계·실제 관찰·사용자 체감을 각각 기록한다. 사용자가 “잘 된다”고 답하거나 일부 표본이 통과해도 전체 검증을 통과로 바꾸지 않는다. 로그가 없거나 접근할 수 없는 항목은 실패 또는 정상으로 단정하지 않고 `미확인`으로 남긴다.

| 점검 범위 | 기록 |
| --- | --- |
| 점검 ID·담당·기준 구조/규칙 버전 | 미정 |
| 점검 기간·선택 흐름·표본과 선정 이유 | 미정 — 정상·예외·최근 변경 등 필요한 표본; V01–V26 중 해당 사례 연결 |
| 읽을 근거·접근 가능한 범위·확인 시각 | 미정 — 로그·결과 ID·설정·사용자 답변; 비밀값·운영 원문 복사 제외 |
| 확인하지 못한 영역·표본의 한계 | 미정 — 다른 기간/계정/시나리오로 결과를 일반화하지 않음 |
| 현재 수행 범위·기존 변경 권한 근거 | 미정 — 점검만/보완 포함; 구조 확인과 변경 실행 권한 구분 |

| 항목·관련 D/F/V | 기대 설계 | 실제 관찰·증거 | 사용자 체감·답변 근거 | 판단·후속 담당·재시험 |
| --- | --- | --- | --- | --- |
| 미정 | 미정 | 미확인 | 미확인 | 미정 — 유지/설정 복구/설계 변경 제안/미확인 중 근거와 함께 기록 |

차이가 있으면 설정이 설계에서 벗어난 것인지, 설계가 실제 필요를 충족하지 못하는 것인지 구분한다. 설정 복구는 현재 유효한 설계와 허용된 변경 범위 안에서 진행하고, 설계 변경 제안은 [구축 결정·규칙 기록](<구축 결정·규칙 기록.md>)의 버전·이유·영향 항목에 연결한다. 실제 조치·재시험·남은 미확인은 위 증거 기록에 남기며, 질문의 답변만으로 조치 완료나 시험 통과를 기록하지 않는다.
