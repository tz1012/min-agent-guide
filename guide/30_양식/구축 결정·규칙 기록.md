# 구축 결정·규칙 기록

이 파일은 앞으로 채울 양식이다. 아래 미정 칸은 설치 완료, 권한 부여 또는 시험 통과를 뜻하지 않는다. 확인된 방향과 선택이 필요한 실제 구성값을 구분한다. [기능 정의](<../최소한의 에이전트 시스템 구축 - 기능 정의.md>)와 [구축·운영 절차](<../10_구축/구축·운영 절차.md>)를 함께 사용한다.

[초기 셋업 흐름](<../10_구축/초기 셋업 흐름.md>)에 따라 먼저 환경을 확인하고, 진행 위치·설치 계획·수동 조치는 [셋업 진행 기록](<셋업 진행 기록.md>)에 연결한다. 이 파일은 D01–D09·규칙·연결 계약의 정본이다. 모든 칸을 먼저 채우려 하지 말고 현재 단계의 의존 항목만 확정한다. 선택하지 않은 서비스·DB·동기화·다중 작업자 항목은 `제외 / 사유 / 재검토 조건`으로 남기며, 이를 구현 착수의 선행 조건으로 삼지 않는다.

- 확인한 답변은 재사용하고, 미정 값은 추정으로 확정하지 않는다.
- 관련 질문을 1–3개씩 묶고, 실제 사례에서 조건·행동·예외·완료 기준을 도출한다.
- 비밀번호·토큰·개인키를 기록하지 않는다. 자격증명은 보관소와 항목 이름 등 참조만 남긴다.

## 가이드의 기본 설계 방향

- 무료 또는 최소 비용 구성을 우선 고려한다. 실제 월 예산·허용 비용은 해당 사용자의 요구에 맞춰 정하며, 이미 확인한 답변은 재질문하지 않는다. 아래 방향은 가이드의 출발점이며 새 사용자의 설정·승인·제품 채택을 대신하지 않는다.
- 개인·기업의 백엔드, 집/외부/모바일 연속성, 내외부 보안 경계·허용·추적을 설계 범위에 포함한다.
- 집 PC·외부 가상 PC·중앙 PC의 담당 서버가 켜졌을 때와 꺼졌을 때 가능한 작업을 구분한다. 자체 웹앱을 필수로 삼지 않고 기존 메신저·Paseo·CLI 접점을 우선 검토한다.
- Google Drive·Docs·Sheets·Forms·Apps Script·Cloudflare·SQLite·Jev·Reason Network의 실제 채택, 계정·제품·요금제·월 예산·외부 전송 권한은 아직 미정이다. 추천 구성을 채택 확정이나 서비스 연결 완료로 기록하지 않는다.
- Sheets의 구조화된 표와 Drive의 본문·첨부를 연결한 전체 논리 DB를 구성 선택지에 포함한다. 기존에 쓰는 시트·연결 파일의 구조부터 확인하고, 로컬 DB와의 차이를 설명한 뒤 정본을 결정한다. SQLite를 필수 구성으로 전제하지 않는다.
- 목표·일정·할 일 연결, 알림과 완료 구분, 기억·스킬 변경 검증, 대화 보관·전사·정리를 셋업 선택지에 포함한다. 이것은 모든 구축에 해당 기능이나 제품을 채택한다는 결정이 아니다.
- 초기 설계와 운영 점검에 문답으로 구조·규칙을 확정하는 절차를 제공한다. LLM Wiki 구성은 사용자 지정 자료를 정리한 [구성 참고](<../90_참고자료/LLM Wiki 구성 참고.md>)를 활용한다. 실제 위키 설치·기존 자료 이관·외부 템플릿 일괄 적용을 확정한 것은 아니다.
- 기본 운영 방향은 에이전트의 선제 관찰·제안·허용된 실행/수정·완료 추적이다. 이 방향은 실제 계정 접근·발신·비용 권한을 대신하지 않는다. 아래 능동 운영 계약에 실제 값과 근거를 정한다.

## 전체 구조 청사진과 문답 근거

청사진 ID·버전·상태: **미정 / 미정 / 미작성**. 비교할 이전 버전·변경 이유·영향받는 결정/검증 ID: **미정**. 사용자가 구조 내용을 확인한 근거·범위: **없음**. 내용 확인은 설치·외부 변경·비용 발생의 포괄 승인이 아니다.

## 배치·기기 연속성·저장소 결정

[백엔드 설계](<../10_구축/백엔드·기기 연속성·비용 설계.md>)의 후보를 참고해 필요한 칸만 확정한다.

기존 DB·표·파일과 실행기의 내장 기능이 각각 무엇을 맡는지 먼저 확인한다. 내장 세션 저장은 실행기 재개를 위한 상태일 수 있으며 업무 데이터의 정본 결정과 구분한다. 필요한 업무 상태·관계·실행 이력을 Sheets+Drive에 저장하는 설계도 가능하고, 내장 기능·파일만으로 충족하면 별도 업무 DB를 만들지 않는다. 임대·세대 번호는 다중 작업자나 자동 인계를 선택할 때, 문서 커서·충돌 처리는 동기화를 선택할 때 구체화한다. 실제 경로·설치 계획은 셋업 진행 기록에 연결한다.

| --- | --- |
| 기존 저장 구조 조사·재사용 범위 | 미정 — 시트/테이블·고정 ID·관계·파일 참조·읽기/쓰기 주체·표본 범위·확인하지 못한 부분; 운영 원문은 이 양식에 복사하지 않음 |

## Jev·Reason Network 도입 검토

[선택 구성 검토·최종 체크리스트](<../10_구축/선택 구성 검토·최종 체크리스트.md>)를 적용한다. 두 행은 모든 구축에서 검토하고 남기되 제품 설치는 도입한 경우에만 진행한다. 아래 `미정`은 미도입이나 보류로 확정된 값이 아니다. 개인/기업 영역별 판단이 다르면 행을 나눈다. 기존 답변·선택 근거를 재사용한다.

| 항목·관련 D | 해결할 문제·현재 근거 | 결정·이유·결정자/시각 | 미도입 대안·보류 영향/담당/재검토 조건·기한 | 도입 시 설정/버전·권한/비용·설치/시험 참조 |
| --- | --- | --- | --- | --- |
| Jev — D03/D04/D06/D07 | 미정 — 반복 의미 판단의 품질·지연·비용 | 미정 — 도입/미도입/보류 | 미정 | 미정 — V03/V09/V19/V20 중 적용 |
| Reason Network — D03/D04/D06/D07/D08 | 미정 — 기기·하네스 간 실제 협업 필요 | 미정 — 도입/미도입/보류 | 미정 | 미정 — 참여 기기/하네스·폴더·수신 정책·설정 변경; V03/V05–V08/V15–V17/V19 중 적용 |

추가로 검토한 선택 제품도 같은 표에 행을 남긴다. 최종 체크리스트·구축 보고서는 이 결정을 참조하며 미도입은 `적용 제외 + 근거`, 도입 후 미시험은 `미검증`으로 구분한다.

### 분류 기능의 선택 방식과 계약

### Sheets·Drive DB를 선택한 경우

[Google 도구 기반 최소 구성](<../10_구축/Google 도구 기반 최소 구성.md>)의 역할 후보를 실제 필요와 대조한다. Sheets의 테이블과 Drive의 본문·첨부를 연결해 전체 논리 DB로 사용할 수 있다. 업무표·조회 화면으로만 역할을 제한하지 않으며, 기존 구조를 확인한 뒤 필요한 테이블과 연결만 채택한다. Drive·Docs·Sheets를 모두 새로 도입하거나 SQLite를 함께 만드는 것은 필수가 아니다. 다음 값은 전부 미정이며 연결·외부 쓰기·자동 실행이 허용됐다는 뜻이 아니다.

| --- | --- |

| 비용·검증·운영 책임 | 미정 — 계정/저장/API/자동화/모델별 한도·총비용·초과 동작·운영 담당·공식 근거/확인일; 검증 기록의 Google 표본 중 적용 범위 |

사람의 직접 편집을 허용할 영역과 에이전트가 실행 상태를 갱신할 영역을 먼저 정한다. 제안·결과 열은 가능한 방식 중 하나이며, 직접 편집이 필요하면 허용 열·조건·쓰기 순서·수식 보존·복귀를 확정한다. 버전을 읽고 비교한 뒤 쓰는 절차 사이에는 다른 수정이 들어올 수 있으므로, 강한 동시 갱신 보장이 필요한 업무는 선택한 직렬화 수단의 실제 범위를 검증하거나 다른 DB를 검토한다. Sheets와 Drive를 함께 바꾸는 작업은 단일 트랜잭션으로 취급하지 않는다.

개인/기업별 접근 경계와 승인 근거가 필요한 행동은 표의 체크 여부만으로 판단하지 않는다. Sheets+Drive를 전체 업무 DB로 선택하면 요청·실행 이력도 정한 계약으로 관리할 수 있으나, 실행기 고유 세션·재개 기능까지 자동 대체되는 것은 아니다. 해당 세션과 정본의 ID·역할을 연결하며 같은 업무 상태를 별도 로컬 DB에서도 독립 확정하지 않는다.
