# Claude를 사용할 경우

이 안내의 파일 기반 설정은 Claude Code 기준이다. 다른 Claude 환경에서는 폴더를 열거나 파일을 제공한 뒤 [README](../README.md)와 [AGENTS.md](../AGENTS.md)를 명시적으로 읽도록 요청한다.

## 시작과 개인 설정

- 패키지 루트의 `CLAUDE.md`는 짧은 공통 `AGENTS.md`를 가져온다. 가져오기나 자동 발견이 지원되지 않으면 두 파일을 직접 읽는다.
- 개인 전역 지침의 기본 위치는 `~/.claude/CLAUDE.md`, 프로젝트 지침은 프로젝트의 `CLAUDE.md`다. 개인 프로젝트 예외는 `CLAUDE.local.md`로 구분하고 공유 저장소에서 제외할 수 있다.
- 여러 `CLAUDE.md`는 문맥에 함께 들어간다. 스킬 이름 충돌 시의 선택 순위와 지침 문맥 결합을 혼동하지 않는다.
- 반복 절차가 확정되면 프로젝트 `.claude/skills/<이름>/SKILL.md`로 만들 수 있다. 개인 공통 스킬은 `~/.claude/skills`에 둔다.
- 동명 스킬은 기업 관리 → 개인 → 프로젝트 순으로 선택된다. 플러그인 스킬은 `/플러그인명:스킬명`처럼 구분되므로 팀 절차가 개인 스킬에 가려지지 않게 이름과 호출 방법을 정한다.

## 필요한 규칙만 읽기

- `@path`로 나눈 문서를 모두 가져오면 입력량이 줄지 않는다. 이 패키지에서는 짧은 공통 원칙만 가져오고 상세 절차는 작업에 맞게 읽는다.
- 작업별 절차는 스킬로, 특정 파일에만 적용하는 규칙은 `.claude/rules`의 `paths` 조건으로 분기할 수 있다. 조건 없는 규칙은 시작 시 로드된다.
- 호출된 스킬 본문은 이후 턴에도 남을 수 있으므로 본문과 긴 참조 자료를 구분한다. 적용 파일은 `/memory` 또는 `/context`에서 확인한다.

## 엔터프라이즈 설정

- 조직 지침·팀 절차·개인 선호의 변경 담당과 범위를 구분한다.
- 조직 공용 스킬 배포와 필수 정책 집행을 구분한다. 계정 기반 조직 배포는 제공 대상과 사용 여부를 확인하고, 그룹별 플러그인 제공은 해당 Enterprise 기능 범위에서 구성한다.
- 실행 제한은 관리형 설정과 연결 서비스 권한으로 집행한다. 로컬/클라우드 지원 범위, 실제 적용 정책과 변경 가능한 기본값을 기록한다.
- 원문에 있는 과거 특정 사용자의 승인 규칙이나 운영 환경을 현재 조직 정책으로 복사하지 않는다.

## 구축·확인

[초기 셋업 흐름](<../10_구축/초기 셋업 흐름.md>)으로 환경 확인부터 진행하고, 현재 단계에 필요한 값만 [결정·규칙 양식](<../30_양식/구축 결정·규칙 기록.md>)에 채운다. [공통 구축 절차](<../10_구축/구축·운영 절차.md>)의 해당 항목으로 현재 로드된 지침, 적용 스킬, 허용/거부 동작의 증거를 남긴다. 이 패키지는 Claude 설정이나 스킬을 이미 설치한 상태가 아니다.

## 능동 실행과 미완료 재점검

Claude Code를 운영 실행기로 선택하면 [능동 운영과 완료 추적](<../10_구축/능동 운영과 완료 추적.md>)을 실제 시작 장치에 연결한다. CLAUDE.md·스킬은 행동 지침이고 예약·실행 프로세스를 대신하지 않는다.

| 경로 | 사용 조건·설정 |
| --- | --- |
| 세션 `/loop` | 진행 중 세션의 간격 점검에 사용. 현재 공식 문서는 재개 시 만료되지 않은 작업 일부를 복원하지만 예외가 있으므로 무조건 영구 유지나 무조건 소실로 설명하지 않음. 해당 세션/프로세스가 살아 있어야 실행 |
| Desktop 예약 | Scheduled에서 로컬 폴더·프롬프트·주기·권한을 설정. 앱이 열려 있고 컴퓨터가 깨어 있어야 실행. 작업 디렉터리의 미커밋 변경/선택 worktree와 결과 회수 방법 확인 |
| Cloud 예약 | 접근 가능한 저장소·환경·연결·트리거를 설정. 로컬 PC OFF에도 실행할 수 있으나 로컬 전용 파일이 자동 제공되지는 않음. 실제 계정/조직의 기능 제공과 권한 확인 |
| CLI + 외부 스케줄러 | `claude -p`로 비대화형 호출. 필요한 도구·출력 형식·세션 지정·권한을 고정하고 업무 상태·알림·호스트 감독은 운영 어댑터로 연결 |

[세션 예약](https://code.claude.com/docs/en/scheduled-tasks), [Desktop 예약](https://code.claude.com/docs/en/desktop-scheduled-tasks), [Cloud 예약](https://code.claude.com/docs/en/routines), [비대화형 실행](https://code.claude.com/docs/en/headless)

1. 설치 버전과 실제 사용 표면을 확인하고 위 경로 중 목적에 맞는 하나를 선택한다. 같은 업무에 `/loop`와 별도 예약을 중복 담당으로 두지 않는다.
2. 관찰 대상·허용 수정·완료 근거·다음 점검·상한을 프롬프트/스킬과 업무 정본에 연결한다. 비대화형 `--bare` 등의 옵션이 지침·기억·도구 자동 로딩을 생략할 수 있으므로 실제 로딩을 확인한다.
3. 업무 `taskId`와 Claude 세션/run 참조를 따로 저장한다. 종료 코드·응답 JSON·실제 변경을 대조하고 미완료만 다음 회차에 넘긴다. 초안/발송·허용 대상·결과 안내도 따로 확인한다.
4. [P01–P06](<실행기 독립 운영 검증.md>)으로 채팅을 닫은 뒤 시작·허용 수정·검증·다음 회차·중지/회수를 시험한다. 사용자/관리자 승인이 필요한 행동은 대기/인계하며 무인 편의를 위해 정책을 넓히지 않는다.

현재 환경 PATH에 `claude`가 없으므로 로컬 버전/도움말·모델·예약·실제 계정 실행을 확인하지 않았다. 공식 문서의 지원과 이 사용자의 설치 완료·운영 성공을 구분한다.
