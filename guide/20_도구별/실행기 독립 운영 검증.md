# 실행기 독립 운영 검증

**어떤 에이전트로 구축했는가와, 누가 지속적으로 관찰·실행·재점검하는가는 별개다.** OmO·OpenClaw·Hermes·Codex·Claude 중 선택한 실행기를 [능동 운영과 완료 추적](<../10_구축/능동 운영과 완료 추적.md>)의 같은 운영 계약에 연결한다. 마스터 지침이나 스킬 파일만 전달한 상태는 예약·상주 서비스·작업 상태·알림이 설정된 상태가 아니다.

이 문서에서 OmO는 `code-yeongyu/oh-my-openagent`의 **OmO Native**, ‘가재’는 **OpenClaw**를 뜻한다고 가정한다. 실제 설치된 제품·패키지·에디션·버전을 확인해 다르면 해당 공식 경로로 다시 분기한다. OmO의 옛 OpenCode 플러그인과 Codex edition은 별도다.

## 1. 동일하게 갖춰야 하는 운영 역할

| 역할 | 실행기와 무관한 완료 조건 |
| --- | --- |
| 관찰·시작 | 예약·이벤트·상태 변화 중 선택한 실제 트리거가 사용자 새 메시지 없이 실행기를 깨움; 대상·시간대·활동 시간·호스트 조건 기록 |
| 상태·담당 | 업무 `taskId`, 이번 `runId`, 관찰 근거·시각, 상태·다음 점검 시각, 담당 실행기·중복 방지·소유권을 지속 저장 |
| 허용된 행동 | 관찰 결과에 필요한 행동 중 이미 허용된 수정만 진행; 범위 밖은 결정 요청으로 남기고 독립 작업은 계속 |
| 검증·재점검 | 실제 결과를 재조회하고 완료 기준을 검사; 부족하면 원인·다음 행동·기한을 남기고 한도 안에서 다시 점검 |
| 안내·제안 | 중요 변화·결정 필요·완료 근거·다음 행동을 정한 접점으로 전달; 무응답·알림 전송·모델의 완료 선언을 업무 완료로 처리하지 않음 |
| 중지·복귀 | pause/snooze/권한 회수·호스트 OFF·재부팅·시간 초과를 다루고, 복귀 시 오래된 승인과 실제 외부 결과를 대조 |

새 DB나 스케줄러를 무조건 설치하지 않는다. 기존 실행기의 기능이 위 역할을 충족하면 그대로 쓰고, 부족한 부분만 어댑터·기존 저장소·외부 스케줄러로 보완한다. 작업 상태와 제품 내부 세션 상태는 다른 책임이며 연결 ID로 묶는다.

## 2. 제품별 경로와 대체 구성

아래 표는 2026-10-28에 확인한 **문서상 구성 가능 경로**다. 실제 계정의 기능 제공·설치 버전·권한·수용시험 통과를 뜻하지 않는다. 구체적인 명령·설정은 연결된 제품 문서를 따른다.

| 실행기 | 예약·능동 시작 | 비대화형 실행·지속 상태 | 알림·호스트 조건·미지원 시 대체 |
| --- | --- | --- | --- |
| [Codex](Codex.md) | 앱의 Scheduled 지원 범위 또는 외부 스케줄러가 CLI 호출; CLI 자체 Scheduled 관리 UI로 가정하지 않음 | `codex exec`, JSONL 결과·세션 재개; 별도의 업무 상태/완료 근거와 연결 | 앱 결과함 또는 허용 발신 어댑터. 로컬 파일 작업은 해당 호스트와 필요한 앱/실행기가 켜져 있어야 함. 외부 스케줄러+CLI+상태로 보완 가능 |
| [Claude Code](Claude.md) | 세션 `/loop`, Desktop 예약, Cloud 예약 중 선택; 단기 세션 루프와 독립 예약 구분 | `claude -p`, JSON 결과·명시 세션 재개; 로컬 또는 클라우드의 실제 저장 범위 확인 | 로컬 예약은 PC·앱 ON, Cloud는 접근 가능한 저장소/연결 필요. 해당 기능이 없으면 외부 스케줄러+CLI+허용 발신 어댑터 |
| [Hermes](Hermes.md) | gateway cron, 세션 `/heartbeat`·`/loop` 중 실제 버전 지원 기능 | cron의 실행 기록·세션 상태 재사용; `--oneshot`은 무인 권한 동작을 별도 검토 | gateway의 전달 대상 또는 선택한 발신 어댑터. 관련 gateway/backend 프로세스 ON; cron 정의만 저장한 상태로 실행된다고 하지 않음 |
| [OpenClaw](OpenClaw.md) | 현행 Automations. 구 heartbeat monitor는 일반 job으로 이관 | Gateway 예약·실행 이력, `openclaw agent` 또는 지원 버전의 `agent exec`; 임시 상태와 유지 상태 구분 | job delivery 또는 발신 어댑터. Gateway 기반 예약은 Gateway ON; 독립 CLI는 외부 스케줄러·상태·호스트 감독 필요 |
| [OmO Native](OmO.md) | 세션의 작업 지속과 정시 예약을 구분; 확인한 문서만으로 공통 상시 예약기가 있다고 가정하지 않음 | Native의 현재 print/JSON/RPC 지원을 실제 도움말로 확인해 어댑터 연결. 세션 재개와 업무 정본을 별도 매핑 | 외부 스케줄러·상태·허용 발신 어댑터 구성 가능. legacy `oh-my-openagent run`을 Native 명령으로 오기하지 않음; 실제 Native 호출 확인 전 후보 상태 |

공식 근거: [Codex Scheduled](https://learn.chatgpt.com/docs/automations), [Codex CLI](https://learn.chatgpt.com/docs/cli/reference), [Claude 예약 비교](https://code.claude.com/docs/en/scheduled-tasks), [Claude 비대화형 실행](https://code.claude.com/docs/en/headless), [Hermes cron](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron), [OpenClaw Automations](https://docs.openclaw.ai/automation/cron-jobs), [OmO 공식 안내](https://omo.dev/docs).

## 3. 에이전트가 실제로 설정할 순서

1. **대상 식별:** 구축 도구·운영 실행기·버전·에디션, 설치 위치, 실행 OS/계정, 실제 프로젝트·저장소를 확인한다. 로컬 도움말과 공식 문서가 다르면 실제 버전의 기능을 기준으로 기록한다.
2. **원칙 연결:** README와 AGENTS 및 필요한 제품 문서·능동 운영 지침을 읽게 한다. 무인 모드가 지침·스킬·도구를 생략하는 옵션을 쓰는지 확인한다. 실제 로드된 지침 버전과 경로를 기록한다.
3. **시작 장치 설정:** 기존 예약/이벤트 연결을 재사용하거나 OS 스케줄러·승인된 클라우드 트리거를 택한다. 정확한 명령/설정 경로, 실행 계정·작업 디렉터리·시간대·다음 회차·OFF 복구·동시 실행 방지를 남긴다. 같은 업무에 네이티브와 외부 예약을 중복 등록하지 않는다.
4. **입출력 계약 구현:** 실행기에 `taskId`, 관찰 범위·정본 위치·권한 정책 버전·시간/비용 상한을 전달하고, 구조화 결과·실행 상태·근거·다음 행동을 회수한다. 제품 내부 세션 ID를 전체 업무의 유일한 ID로 삼지 않는다.
5. **권한·발신 설정:** 무인 실행에서 사람이 응답해야 하는 요청은 `waiting_approval`/차단으로 처리한다. 편의상 전체 권한·승인 우회로 바꾸지 않는다. 실제 사용자/조직 권한과 허용된 변경·발신 대상은 실행 계층에서도 제한한다.
6. **기동·시험:** 허용된 표본에서 P01–P06을 수행한다. 자동 트리거·실제 수정·검증·새 회차 재점검·결과 안내를 직접 확인하고, 수동 실행 한 번 성공한 것을 자동화 전체 성공으로 대체하지 않는다.
7. **인계:** 상태/로그 확인, 재인증, 중지·snooze·재개, 비용 조회, 호스트 OFF 한계, 남은 미검증 항목을 사용자에게 안내한다. 관련 실제 값은 기존 [결정 기록](<../30_양식/구축 결정·규칙 기록.md>)·[진행 기록](<../30_양식/셋업 진행 기록.md>)·[검증 기록](<../30_양식/검증·운영 기록.md>)에 남긴다.

### 외부 스케줄러로 CLI를 운영할 때

Linux의 서비스/타이머, macOS의 launchd, Windows의 작업 스케줄러, 승인된 CI/클라우드 실행기 중 대상 환경에 맞는 하나를 선택한다. **이 문서는 예약을 설치하지 않는다.** 설치 단계에서는 해당 OS의 실제 명령·파일·시작/중지·상태 조회·복구 방법까지 구체화해야 한다.

한 회차의 어댑터는 다음 책임을 갖는다.

- 실행 전에 중지 상태·권한·기한·예산을 확인하고, 기존 작업을 찾은 뒤 원자적인 담당 획득 또는 검증된 직렬화로 중복 실행을 막는다.
- 관찰한 최신 자료를 근거로 CLI를 호출한다. 시간 상한·프로세스 종료/정리·자식 작업의 정착 여부를 추적한다. 프로세스 종료 코드와 업무 완료를 구분한다.
- 부분 성공과 결과 미확인을 보존한다. 외부 변경 뒤 응답이 끊기면 실제 결과를 대조하기 전 재실행하지 않는다.
- 모델의 응답을 형식 검증하고 실제 결과와 대조한다. 미완료면 같은 작업에 다음 점검을 기록한다. 매 회차마다 새 예약을 무한 생성하지 않는다.
- 전달 실패와 업무 실패를 구분하며 같은 결과 알림만 재시도한다. 보낼 내용·대상·중복 키와 실제 수락/전달 증거를 남긴다.
- 실행기를 호출하는 프로세스가 꺼져 있으면 아무 일도 진행되지 않는다. 휴대폰에서 대화가 보이는 것과 서버에서 작업이 실행 중인 것은 다르다.

이 외부 경로는 설계 대안이다. 선택한 CLI의 입력·도구 권한·결과 형식·종료 조건이 실제로 확인되기 전에는 운영 가능으로 확정하지 않는다.

## 4. 실행기를 교체할 때 유지할 것

Codex로 만든 시스템을 Hermes/OpenClaw/OmO/Claude로 운영하거나 그 반대로 바꿀 수 있게 다음을 검사한다. 제품 내부 DB를 다른 제품의 DB로 그대로 복사하지 않는다.

1. 현재 예약과 새 작업 접수를 정한 범위에서 멈추고, 실행 중 작업·하위 작업·외부 결과를 대조한다. 담당 락의 시간 만료만으로 이전 실행이 중단됐다고 판단하지 않는다.
2. 업무 정본의 `taskId`, 현재 상태·완료 근거·미확인 변경, 정책 버전·승인 범위/유효 기간, 다음 점검 시각, 알림 중복 기록을 유지한다. 이전/새 제품의 세션·run ID는 별도의 참조로 매핑한다.
3. 상태 스키마·시간대·파일 경로·도구 결과·사용자/조직 ID의 의미를 변환표로 확인한다. 읽을 수 없는 상태를 초기 완료나 신규 작업으로 조용히 바꾸지 않는다.
4. 새 실행 계정에서 원본 접근·쓰기·발신 권한을 다시 시험한다. 이전 제품의 자격증명이나 관리자 권한이 자동 승계된다고 가정하지 않는다.
5. 하나의 실제 작업 담당과 하나의 활성 예약만 유지한다. 잔존 프로세스가 없음을 확인하고 새 담당 권한/버전을 발급한 뒤 인계한다. 분산 실행이면 오래된 담당의 쓰기를 막는 검증 수단도 필요하다.
6. 미완료·부분 성공·권한 대기·snooze 표본을 새 실행기에서 P03/P04/P06으로 검사한다. 실패하면 새 시작을 중지하고, 대조한 상태를 기준으로 이전 실행기로 복귀한다. 확인 없이 두 실행기를 동시에 재개하지 않는다.

## 5. 같은 수용시험 P01–P06

P 번호와 의미는 [능동 운영과 완료 추적](<../10_구축/능동 운영과 완료 추적.md>)과 동일하다. 제품마다 선택한 동작에 대해 각각 기록한다. 네이티브 기능이 없는 제품은 대체 어댑터까지 포함해 통과해야 한다.

| 시험 | 각 실행기에서 실제로 볼 것 | 기존 검증 |
| --- | --- | --- |
| P01 선제 시작 | 원래 채팅/화면을 닫고도 정한 예약·이벤트가 작업을 시작; 실제 호스트·트리거 ID·첫 관찰 시각 확인. CLI만 종료되고 다음 회차를 시작할 장치가 없으면 실패 | V01/V10/V15 |
| P02 최신 근거 계획 | 선택한 아침·낮·저녁 흐름이 최신 목표/일정/할 일/지식을 조회하고 근거·시각·다음 행동을 제안; 단순 고정 문구 반복과 구분 | V21/V24/V25, 선택 시 V26 |
| P03 수정·재검사 | 누락/실패 표본을 허용 범위 안에서 수정하고 재검증; 미완료면 이유·담당·다음 점검 시각, 한도 초과면 중단/인계 | V02/V06/V07/V10 |
| P04 중복·재개 | 같은 이벤트와 응답 유실·재시작에서 기존 `taskId`와 실제 외부 결과를 사용; 중복 변경·이중 담당·중복 알림 방지 | V05/V06/V07 |
| P05 OFF·한도 | 호스트 OFF·누락 회차·시간대/활동 시간·토큰/호출/비용 상한을 시험; 복귀 시 만료 업무를 무조건 몰아 실행하지 않음 | V09/V10/V16/V19 |

## 6. 증거 수준과 이번 확인 결과
