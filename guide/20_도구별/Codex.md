# Codex를 사용할 경우

## 시작

이 폴더의 루트를 작업 디렉터리로 열고 [AGENTS.md](../AGENTS.md)와 [README](../README.md)를 읽도록 요청한다. 자동 지침 발견에 의존하지 않아도 명시적으로 문서를 읽어 구축을 진행할 수 있다. 사용 환경의 상위 지침·권한도 함께 적용된다.

## 개인 시스템

- 이 패키지의 `AGENTS.md`는 프로젝트 공통 원칙이다. 개인 전역 선호는 기본적으로 `~/.codex/AGENTS.md`에 두지만, 이 폴더를 읽기 위해 그 파일이 필요한 것은 아니다.
- Codex는 전역 지침과 저장소 루트부터 현재 작업 폴더까지의 지침을 조합한다. 가까운 폴더가 앞선 지침보다 우선하며, 같은 위치에서 `AGENTS.override.md`가 있으면 먼저 선택된다.
- 실제 반복 절차가 확정되면 프로젝트 `.agents/skills/<이름>/SKILL.md`에 배치할 수 있다. 개인 공통 스킬의 기본 위치는 `~/.agents/skills`다.
- 스킬 설명에는 사용 조건을 구체적으로 쓰고, 본문에는 핵심 절차·완료 확인을 둔다. 같은 이름의 스킬이 병합된다고 가정하지 않는다. 필요하면 이름을 구분하고 `/skills` 또는 `$` 선택으로 확인한다.

## 엔터프라이즈 시스템

- 조직·팀·개인의 수정 범위와 담당자를 먼저 정한다. 관리자 공용 스킬 위치의 예는 `/etc/codex/skills`이며, 팀 절차는 저장소에 배포할 수 있다.
- 필수 실행 제한은 지원되는 관리자 `requirements.toml`과 원본 서비스 권한으로 집행한다. `AGENTS.md`나 스킬 내용만으로 권한 제한을 강제할 수 있다고 가정하지 않는다.
- 관리자 요구사항, 변경 가능한 기본 설정, 워크스페이스 권한, 외부 서비스 권한을 구분한다. 로컬·클라우드·앱별 적용 범위는 동일하지 않을 수 있다.

## 구축·확인

1. [결정·규칙 양식](<../30_양식/구축 결정·규칙 기록.md>)에서 구축 도구와 실제 운영 실행기를 별도로 기록한다.
2. [초기 셋업 흐름](<../10_구축/초기 셋업 흐름.md>)으로 환경 확인·단계별 결정·설치·재개를 진행하고, 해당 단계에서 [공통 구축 절차](<../10_구축/구축·운영 절차.md>)를 읽는다. 이 폴더에 작업별 스킬이 이미 설치되어 있다고 가정하지 않는다.
3. 현재 버전·실제로 읽은 지침 경로·선택한 스킬·권한 설정을 기록하고 정상/거부 동작을 확인한다.
4. 큰 마스터 문서를 만드는 대신 작업 조건에 따라 상세 문서를 읽는다. 원문 자료는 자동 적용 지침으로 로드하지 않는다.

## 능동 실행과 미완료 재점검

Codex로 구축했다면 [능동 운영과 완료 추적](<../10_구축/능동 운영과 완료 추적.md>)을 운영 실행기에 연결하고 [실행기 독립 운영 검증](<실행기 독립 운영 검증.md>)의 P01–P06을 적용한다. AGENTS.md·스킬을 만들거나 대화에서 “나중에 확인하겠다”고 말한 것만으로 예약이 설정되지는 않는다.

- **앱의 예약을 선택:** 제공되는 Scheduled 화면에서 프로젝트·프롬프트/스킬·주기·시간대·실행 위치·권한을 정하고 저장된 다음 회차를 확인한다. 로컬 프로젝트는 컴퓨터·앱이 켜져 있고 폴더가 접근 가능해야 한다. 웹 예약은 로컬 폴더를 직접 유지하는 실행 환경과 구분한다. 실제 사용 가능한 기능·플랜·조직 정책을 확인한다. [공식 Scheduled 안내](https://learn.chatgpt.com/docs/automations)
- **CLI를 운영 실행기로 선택:** 외부 스케줄러/이벤트 수신기가 `codex exec`를 호출하도록 구성할 수 있다. CLI의 Scheduled 관리 화면이 있다고 가정하지 않는다. 실행 계정·작업 디렉터리·지침·도구·sandbox·인증 참조·시간/비용 한도를 고정하고, 구조화 결과와 외부 업무 상태를 연결한다. CLI/에이전트 서버가 존재한다는 사실만으로 반복 작업이 등록된 것은 아니다.
- **상태와 재개:** 로컬 `0.162.1` 도움말에서 `exec`, `exec resume`, `--json`, `--output-schema`, `--output-last-message`, `--ephemeral`의 존재를 확인했다. 지속 상태가 필요한 경로에서 ephemeral을 선택하면 별도 정본이 유지되는지 검사한다. 명시적 업무·세션 ID로 재개하고, 여러 업무가 있는 환경에서 무조건 가장 최근 세션을 이어받지 않는다. 이 옵션 확인은 모델 실행 성공 증거가 아니다. [CLI 참고](https://learn.chatgpt.com/docs/cli/reference)
- **완료와 안내:** 프로세스 성공·모델의 마지막 응답과 실제 업무 완료를 구분한다. 미완료 원인·다음 점검·허용된 수정과 결과 검증을 저장하고 다음 회차에서 읽는다. 앱 결과함 또는 허용된 발신 어댑터로 다음 행동을 안내하며 수신자 무응답을 완료로 바꾸지 않는다.

설정 에이전트는 정확한 스케줄러 파일/명령·실행 경로·시작/중지·로그·재개 방법을 기존 진행 기록에 남긴다. 무인 실행에서 승인을 받을 수 없는 행동은 대기/차단으로 처리하고 광범위한 승인·sandbox 우회를 기본 대안으로 사용하지 않는다. 실제 자동 회차·OFF 복귀·중복 방지·권한 회수까지 통과한 범위만 능동 운영 완료로 기록한다.
