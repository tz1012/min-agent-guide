# 접속 경계와 보안 운영

집의 Mac mini, 외부 노트북, 태블릿·휴대폰에서 같은 작업을 이어가면서 **누가 어느 단말에서 어떤 자료와 기능을 사용할 수 있는지** 정하는 설계안이다. 기업에서는 사내·사외 접속, 관리·비관리 단말, 직원·외부인·서비스 계정의 경계를 더한다. 아직 제품 선택·정책 확정·설정·시험은 수행하지 않았다.

[기능 정의](<../최소한의 에이전트 시스템 구축 - 기능 정의.md>)와 [구축·운영 절차](<구축·운영 절차.md>)를 함께 사용한다. 결정은 [결정·규칙 기록](<../30_양식/구축 결정·규칙 기록.md>), 실제 적용·시험·운영 증거는 [검증·운영 기록](<../30_양식/검증·운영 기록.md>)에 남긴다. 아래 표는 확정 정책이 아니라 사용자의 환경에 맞춰 채택·수정할 초안이다.

## 1. 위치보다 사용자·단말·자료·행동을 함께 판단

NIST SP 800-207은 사내망이나 회사 소유 단말이라는 이유만으로 신뢰를 부여하지 않으며, 자원에 접속하기 전 사용자·단말의 인증과 인가를 구분한다. 이를 이 패키지에서는 접속 위치 외에 계정, 단말 상태, 대상 자료와 요청 행동을 함께 확인하는 원칙으로 적용한다. 이 설계가 특정 인증 취득이나 조직 규정 준수를 증명하는 것은 아니다. [NIST SP 800-207](https://csrc.nist.gov/pubs/sp/800/207/final)

- 공통
	- 흐름을 `사용 단말 → 접속 인증·정책 → 업무 앱·작업 상태 → 실행기 → 원본 서비스`로 나누고 각 경계의 집행 위치를 기록한다.
	- 화면에 버튼을 숨기는 것만으로 제한하지 않는다. 서버에서 확인한 신원으로 작업·파일의 소유권과 행동 권한을 검사한다. 브라우저가 보낸 사용자 ID를 그대로 신뢰하지 않는다.
	- 허용된 일상 조회·편집은 정한 정책 안에서 수행한다. 모든 파일 읽기나 문서 갱신마다 사람 승인을 요구하지 않는다. 권한 확대·새 반출 대상·정책상 승인 행동만 추가 판단 대상으로 삼는다.
- 개인 시스템
	- Mac mini를 주 실행 호스트로 선택했다면 노트북·모바일은 같은 작업 상태를 보는 접점으로 설계한다. 단말에 API 키와 장기 토큰을 일괄 복사하지 않는다.
	- 기기 잠금·업데이트·분실 대응, 로그인 방식, 사용 중지·재등록 절차를 본인이 수행할 수 있게 남긴다.
- 엔터프라이즈 시스템
	- 사용자·팀·자료 등급·단말 관리 상태·접속 위치별 정책을 조직 담당자와 정한다. 사내망 접속도 업무 권한 검사를 거친다.
	- 일반 업무와 관리자 작업의 계정·권한·실행 경로를 구분하고, 외부 협력자와 임시 권한에는 대상·기간·회수 담당을 둔다.

## 2. 네 가지 경계를 별도로 정하기

| 경계 | 결정할 내용 | 실제 집행·확인 예 |
| --- | --- | --- |
| 인증 | 사용자·서비스·단말을 무엇으로 확인하는가 | 로그인·다중요소 인증·단말 등록·세션 만료, 서버 측 토큰 검증 |
| 인가 | 어떤 작업·자료·기능에 접근할 수 있는가 | 사용자/팀별 조회·편집 범위, 작업 소유권 검사, 원본 서비스 권한 |
| 실행 | 어떤 계정으로 어느 도구·명령을 수행하는가 | 실행기 계정, 작업 폴더, 허용 도구·대상, 쓰기·발송·관리자 기능 제한 |
| 데이터 반출 | 무엇이 어디로 전송·복사·저장되는가 | 모델 제공자·클라우드·다운로드·공유 링크·메시지·로그별 허용 범위 |

로그인 성공이 모든 자료의 열람·관리자 실행·외부 전송 허가를 뜻하지 않는다. 읽기만 하는 기능도 원문을 외부 모델로 보내면 별도의 데이터 이동이 발생한다. 서비스 계정이 자료에 접근할 수 있어도 현재 요청자가 그 자료를 볼 권한이 있는지 별도로 검사한다.

## 3. 역할·위치·단말별 정책 초안

각 행에 데이터 등급·대상·행동·세션 조건·담당자를 붙여 확정한다. 미정인 민감 자료 접근이나 외부 반출은 활성화하지 않고, 이미 허용된 작업은 그 범위에서 계속한다.

| 상황 | 접속 조건 후보 | 허용 범위 후보 | 제한·추가 확인 후보 | 남길 추적 정보 |
| --- | --- | --- | --- | --- |
| 개인: 집 Mac mini 직접 사용 | 본인 OS 계정·잠금·업무 앱 인증 | 본인 업무 조회·편집·선택한 실행 | 관리자 설정·새 연결의 범위 확인 | 사용자·호스트·실행 ID·변경 |
| 개인: 외부의 본인 노트북 | 등록 단말·원격 접속 인증·암호화 경로 | 같은 작업 조회·재개·취소·허용된 편집 | 다운로드·오프라인 복사 범위, 분실 시 회수 | 단말·접속 세션·작업 버전 |
| 개인: 태블릿·휴대폰 | 본인 로그인·기기 잠금·짧은 화면 노출 | 상태 확인·요청·결과 검토·정한 승인 | 알림 미리보기의 민감 내용, 장기 비밀 저장 | 사용자·기기·승인 대상/내용·시각 |
| 기업: 사내 관리 단말 | 조직 계정·단말 상태·업무 역할 | 직무·팀에 허용된 자료·행동 | 사내 위치만으로 권한 확대 금지 | 조직·사용자·단말·정책 결과 |
| 기업: 사외 관리 단말 | 조직이 허용한 원격 경로·인증·단말 상태 | 직무 범위 내 연속 작업 | 자료 등급별 외부 접속·반출 조건 | 외부 접속·정책·자료/행동 ID |
| 기업: 비관리 단말·외부 협력자 | 허용 여부 먼저 결정, 계정·기간·범위 제한 | 허용 시 제한된 웹 조회 등 정한 기능 | 민감 자료·다운로드·클립보드·관리 기능의 허용 여부 | 계약/담당·계정·만료·거부 기록 |
| 공통: 서비스 계정·예약 실행 | 별도 서비스 신원·필요한 범위의 자격증명 | 지정 업무·자료·시간·도구 | 사람 로그인 토큰 공유, 불필요한 전체 관리자 권한 | 서비스 ID·위임 사용자·실행/예약 ID |
| 기업: 운영 관리자 | 구분된 관리자 권한·정해진 관리 접속 | 변경·복구·권한 관리 | 필요한 경우 제한 시간·변경 검토·비상 접근 | 변경 전후·이유·담당·승인 근거 |

브라우저에서 다운로드나 클립보드를 숨겨도 화면 촬영·내용 재입력까지 막는 것은 아니다. 차단 기능이 없는 환경에서는 민감 내용 자체를 표시하지 않거나 접근을 제한하는 대안을 선택한다. 단말 관리·웹 격리 등 기능은 선택한 제품에서 실제 지원·집행되는지 시험한다.

## 4. 기기를 바꾸어도 작업을 잇는 방법

- 공통
	- 작업 상태의 기준 저장소를 하나 정하고 `작업 ID / 소유자 / 현재 단계 / 최신 버전 / 마지막 완료 결과 / 대기 사유 / 다음 행동`을 저장한다.
	- 단말 전환은 같은 작업 ID를 재조회하는 방식으로 처리한다. 접속 화면이 끊긴 것과 서버 작업이 취소된 것을 구분한다. 재접속 시 새 실행을 만들기 전에 기존 상태·외부 결과를 확인한다.
	- 동시에 편집·재개할 때 버전 검사나 잠금으로 충돌을 감지한다. 승인 요청은 대상과 내용·버전에 연결하고, 이미 처리된 승인·실행을 중복 수행하지 않는다.
- 개인 시스템
	- Mac mini의 전원·절전·인터넷·재부팅 상태가 실행 가능 시간에 영향을 준다. 노트북과 모바일에서 호스트 연결 실패를 구별해 표시하고, 호스트 복구 전 새 실행을 무작정 재전송하지 않는다.
	- 노트북에 별도 실행기를 둘 경우 동일 업무를 누가 맡는지 결정한다. 파일 동기화만으로 실행권이 이전됐다고 간주하지 않는다. 이전 실행 정지·상태 인계·자격증명 범위를 확인한 뒤 인계한다.
- 엔터프라이즈 시스템
	- 서버의 작업 소유권과 사용자·팀 권한을 유지한다. 사외 접속이나 단말 변경으로 권한이 넓어지지 않게 한다. 퇴사·직무 변경 시 미완료 작업의 새 담당자와 재승인 필요 여부를 기록한다.

## 5. Tunnel·접속 인증·OAuth 자격증명 구분

Cloudflare Tunnel로 경로를 공개하는 것만으로 사용자 접근이 제한되지는 않는다. Cloudflare는 공개 경로 전에 Access 앱을 구성하고, 원본 서버까지 우회 요청을 막도록 Access 토큰을 검증하는 방법을 안내한다. 사용할 경우 호스트명·경로·정책 누락과 원본 서버 직접 접근을 시험한다. Cloudflare 채택 자체는 아직 미정이다. [Cloudflare 공개 앱 보호](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/)

| 구분 | 역할 | 다른 인증을 대신하는가 |
| --- | --- | --- |
| 네트워크/Tunnel 연결 자격증명 | 원본 실행 환경과 접속 경로 연결 | 사용자 신원·업무 권한·Google 자료 권한을 대신하지 않음 |
| 사용자 접속 세션 | 웹 앱·원격 접점에 누가 들어오는지 확인 | 앱 내부 작업·자료별 인가가 여전히 필요 |
| 서비스 간 접속 자격증명 | 자동 호출 서비스의 접속 신원 확인 | 최종 사용자의 자료 접근 권한과 분리 |
| 외부 서비스 OAuth | 특정 앱·사용자에 허용된 API 범위로 접근 | 원격 단말 인증·조직 반출 허가와 분리 |
| 모델 제공자 키 | 모델 API 호출·과금 계정 지정 | 회사 자료의 해당 모델 전송 허가와 분리 |

Cloudflare Access의 서비스 토큰은 자동 시스템 접속용 Client ID와 Secret으로 구성되며 별도로 만료·회수할 수 있다. 사용자 세션을 취소하는 조치만으로 유효한 서비스 자격증명까지 회수됐다고 판단하지 않는다. [Cloudflare 서비스 토큰](https://developers.cloudflare.com/cloudflare-one/access-controls/service-credentials/service-tokens/)

OAuth를 직접 구현한다면 검증된 라이브러리와 제공자 절차를 사용한다. 공개 클라이언트에는 PKCE를 적용하고 브라우저·모바일 앱에 공통 client secret을 비밀로 보관할 수 있다고 가정하지 않는다. 토큰은 필요한 범위로 제한하며, refresh token의 보호·만료·회전/회수 지원을 확인한다. [IETF RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)

- 개인 시스템: 장기 토큰과 모델 키는 선택한 실행 호스트의 보호된 보관소에 두고, 각 단말은 필요한 접속 세션만 사용하도록 설계한다. 백업에 비밀이 포함되면 암호화·복원 권한·회수 영향을 별도로 정한다.
- 엔터프라이즈 시스템: 조직 비밀 저장소·관리 주체·환경별 분리·교체 절차를 정한다. 개인 계정이나 공유 관리자 키로 조직 전체를 대리하지 않는다. 사용자 위임과 서비스 계정의 적용 범위를 구별한다.

## 6. 회사 자료의 Google Docs·Cloudflare·모델 전송

Google Workspace 관리자는 OAuth 앱과 접근 범위를 관리할 수 있다. 사용자에게 동의 화면이 표시되거나 앱 검증을 통과했다는 사실만으로 그 조직의 모든 자료 처리가 승인됐다는 뜻은 아니다. [Google Workspace 앱 접근 통제](https://knowledge.workspace.google.com/admin/apps/control-which-third-party-and-internal-apps-access-google-workspace-data)

| 결정할 항목 | 개인 시스템 | 엔터프라이즈 시스템 |
| --- | --- | --- |
| 저장·공유 서비스 | 본인 Google 계정·폴더·공유 대상 | 승인된 Workspace 테넌트·공유 드라이브·소유권·외부 공유 범위 |
| 회사 자료 반입 | 회사 자료가 섞이면 해당 조직 규칙 확인 | 자료 등급별 Google Docs/Drive·개인 클라우드 저장 허용 여부 |
| 원격 연결 서비스 | 사용할 접속 경로·계정·노출 범위 | Cloudflare 등 외부 중계 사용 허용 여부, 보안·네트워크 담당과 관리 계정 |
| 데이터 경로 | 원본→실행기→모델→결과→백업 위치 | 처리자·위치·TLS 종료 지점·로그·보존·계약 조건의 조직 기준 충족 여부 |
| 다운로드·복사 | 노트북/모바일 저장·알림 내용 | 비관리 단말·외부 공유 링크·다운로드·클립보드·출력 범위 |
| AI·검색·메모리 | 사용할 제공자와 저장 설정 | 모델/API·검색 색인·임베딩·메모리·관측 도구로 보낼 자료 범위 |

조직의 승인 여부는 **미정**이다. Cloudflare·Google Docs를 쓰지 못하는 경우 기존 승인 VPN·접속 게이트웨이·사내 저장소·승인 모델로 대체할 수 있게 설계한다. 자료 전송 승인은 서비스 도입·계정·자료 등급·허용 행동 단위로 정하고, 이미 확정된 범위의 일상 작업마다 같은 승인을 반복하지 않는다.

## 7. 감사 기록: 요청부터 결과까지 연결

아래 필드는 이 패키지의 감사 추적 설계안이다. NIST SP 800-92의 로그 관리·보호·운영 계획을 참고하되, 문서에 특정 보존 일수나 이 필드 구성이 의무라고 제시돼 있다고 해석하지 않는다. [NIST SP 800-92](https://csrc.nist.gov/pubs/sp/800/92/final)

| 묶음 | 기록할 필드 |
| --- | --- |
| 사건·시간 | event ID, UTC 시각·시간대, 수집원·호스트, 상관관계 ID |
| 주체·접속 | 사용자/서비스 ID, 조직·팀, 단말 ID·관리 상태, 세션 ID, 필요한 경우 접속 IP |
| 작업·대상 | 요청/작업/실행 ID, 행동, 대상 시스템·자료 ID·자료 등급, 실행 계정 |
| 판단·승인 | 적용 정책·버전, 허용/거부·이유, 승인 ID·담당·대상 버전 |
| 실행·결과 | 도구·연결 ID, 시도 번호, 중복 키, 성공/실패/부분 성공, 외부 결과 ID |
| 변경·전송 | 변경 전후 버전 또는 요약, 전송 대상·자료 범위·양, 비밀 참조 이름 |
| 운영·복구 | 지연·비용·오류 코드, 재시도/회수/복구 사건, 수행 담당·검증 근거 |

- 공통
	- 로그인 성공만 남기지 말고 접근 거부, 권한 변경, 자료 반출, 실행·취소·복구를 연결한다. 에이전트의 설명 대신 실제 도구·서비스 결과를 증거로 남긴다.
	- 비밀번호·토큰·인증 헤더·전체 원문·전체 프롬프트를 기본 로그로 저장하지 않는다. 필요한 표본은 마스킹하고 접근·보관 범위를 별도로 정한다.
	- 로그 읽기·쓰기·삭제 권한, 시간 동기화, 위변조 탐지·백업, 수집 실패 알림을 정한다. 중대한 실행에서 필수 로그가 기록되지 않을 때 중단할지 제한 모드로 둘지 결정한다.
- 개인 시스템: 본인이 실행 이력·실패·비용·접속 기기를 확인하고 문제 작업을 찾아 취소·복원할 수 있는 수준으로 시작한다.
- 엔터프라이즈 시스템: 업무 사용자와 감사 열람자를 구분하고, 실행기 계정이 감사 기록을 임의 삭제하지 못하게 한다. 팀 간 기록 접근과 개인정보 최소 수집·조사 권한을 정한다.

## 8. 보존·폐기·권한 회수·사고 복구

- 보존·폐기
	- 실행 로그, 감사 로그, 대화·메모리, 원문, 검색 색인, 결과, 백업마다 보관 기간·책임자·삭제 방법·예외를 정한다. 현재 기간은 모두 미정이며 자동으로 무기한 보존하지 않는다.
	- 원문 삭제·권한 변경이 검색·캐시·메모리에 반영되는지 확인한다. 백업의 지연 삭제·복원 시 재삭제·접근 차단 방식도 기록한다.
	- 정해진 조사·보존 예외가 있으면 권한 있는 담당자가 범위·종료 조건을 기록한다. 민감정보를 디버깅 편의만으로 복제하지 않는다.
- 분실·퇴사·연결 해제
	- 사용자/기기 세션, 원격 접속, 서비스 토큰, OAuth grant·refresh token, 모델 키, 예약 작업을 각각 회수한다. 한 곳의 로그아웃만으로 전체 접근이 끝났다고 판단하지 않는다.
	- 미완료 작업의 중단·인계와 이미 완료된 외부 결과를 확인한다. 기기 로컬 사본·다운로드·백업의 처리와 회수 후 재접속 거부를 검증한다.
- 사고·복구
	- 영향 계정·연결·자료와 실행 ID를 특정하고 필요한 경로·작업을 격리한다. 기록과 복구 지점을 보존한 뒤 노출 자격증명을 회수·교체한다.
	- 정상 상태로 복구하고 정책·단말·키·연결을 재확인한다. 백업 복원으로 폐기한 자격증명이나 예전 권한이 되살아나지 않게 한다.
	- 개인은 본인 대체 접속·복구 수단과 연락 경로를, 기업은 장애·보안·데이터 담당의 인계와 운영 재개 결정 책임을 기록한다.

## 9. 비용·편의·보안의 선택

| 선택 | 비용·편의 측면 | 확인할 보안·운영 측면 |
| --- | --- | --- |
| 기존 Mac mini 실행 | 보유 장비 활용, 기기 간 동일 상태 사용 | 전원·가정 회선 장애·백업·패치·물리 접근 |
| 관리형 서버·접속 서비스 | 상시 운영·중앙 관리 기능 활용 가능 | 정기 비용·데이터 처리자·정책/로그 기능의 계약·요금제 범위 |
| 긴 접속 세션 | 로그인 마찰 감소 | 분실·탈취 시 접근 시간 증가; 민감 행동 재인증과 회수 |
| 로그 축소·짧은 보존 | 저장·수집 비용 감소 | 사고 조사·중복 확인·복구 증거의 부족 |
| 강한 단말 제한 | 노출 가능한 접점 축소 | 개인 모바일·협력자 접근 불편; 지원·예외 처리 비용 |
| 모든 작업의 중앙 실행 | 단말별 비밀·실행 상태 분산 감소 | 중앙 장애·병목·복구 목표, 운영자 권한 집중 |

가격·포함 기능·로그 기간은 고정값을 가정하지 않고 선택 시 확인한다. 먼저 업무의 필수 경계와 복구 목표를 정한 뒤 이를 충족하는 가장 작은 구성을 선택한다. 비용을 이유로 사용자별 권한 검사를 제거하거나 비밀값을 공유하는 대안을 채택하지 않는다.

## 10. 확정할 값과 검증

미정: 주 실행 호스트·대체 호스트, 단말 목록·관리 상태, 인증·세션 만료·재인증, 역할/자료/행동 정책, 외부 접속 경로, 승인된 저장·중계·모델 서비스, 비밀 보관·회수 담당, 로그·데이터별 보존 기간, 복구 시간·허용 손실, 운영·보안 담당, 월 비용 한도. 해당 값은 기존 D03–D09 및 연결 계약에 연결하여 기록한다.

| 시험 | 기대 결과 |
| --- | --- |
| Mac mini에서 시작해 노트북·모바일로 전환 | 동일 작업·최신 상태 확인, 중복 실행 없이 재개·취소·검토 |
| 두 단말의 동시 수정·승인 | 버전 충돌 감지, 같은 외부 변경은 한 번만 수행 |
| 사내/사외·관리/비관리 단말 비교 | 위치만으로 허용하지 않고 확정한 조건·자료·행동 정책 적용 |
| 다른 사용자·팀의 작업 ID 요청 | 자료·결과·로그 조회가 차단되고 거부 근거 기록 |
| 인증 경로 우회·원본 주소 직접 요청 | 인증·정책 우회가 차단됨; Tunnel 사용 시 Access 설정 누락 확인 |
| 회사 자료의 미승인 서비스·개인 계정 전송 | 반출 경계에서 차단·인계, 이미 허용된 업무는 계속 가능 |
| 기기 분실·직무 변경·토큰 회수 | 기존·새 세션과 서비스 재접속이 정한 범위에서 거부됨 |
| 호스트 장애·로그 장애·백업 복원 | 실제 외부 결과와 상태 대조 후 복구, 폐기한 권한·비밀 복원 방지 |

각 시험의 입력·정책 버전·실제 결과·증거·확인 시각을 남긴다. 현재는 시험 계획이며 실제 보안 설정이나 검증 완료를 뜻하지 않는다.
