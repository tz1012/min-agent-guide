# 대화 수집·전사·지식화

대화 내용을 다시 찾고, 전사문·요약·지식·후속 할 일로 활용하려는 사용자가 선택하는 기능이다. [초기 셋업 흐름](<초기 셋업 흐름.md>)에서 필요 여부부터 확인한다. 대화 기능이 필요 없으면 제외하고 다른 업무의 구축을 계속한다. 이 문서는 설계와 질문 절차이며 실제 녹음·계정 연결·자료 수집은 아직 수행하지 않았다.

원하는 결과와 처리 규칙을 먼저 정하고, 그 역할을 기존 녹음 앱·회의 서비스·채팅 내보내기·전사 도구가 충족하는지 확인한다. 모든 대화를 상시 녹음하거나 새 회의 봇·DB·유료 전사 서비스를 설치하는 것을 기본값으로 두지 않는다. 이 문서에서 ‘전체 보관’은 **사용자가 선택한 대화 범위의 원본 보관**을 뜻한다.

지식관리·라이프 관리·기업 업무는 복수 또는 전체 선택할 수 있다. 대화 수집·전사 기능은 선택한 여러 흐름에서 함께 사용할 수 있지만, 처리 기능을 공유한다는 이유로 개인·기업의 원문·기억·권한을 합치지 않는다. 첫 시험 한 건을 정하는 것은 적용 범위를 하나로 제한하는 선택이 아니다.

## 1. 셋업 질문의 분기

이미 답한 개인/기업 범위·호스트·계정·예산·허용 정책은 재사용한다. 아래 질문을 전부 한 번에 묻지 않고, 현재 단계에서 선택한 기능에 필요한 미정 사항만 1–3개씩 묻는다. 사용자의 답변은 [결정·규칙 기록](<../30_양식/구축 결정·규칙 기록.md>)의 D01–D09와 해당 연결 계약에 기록한다. 이 문서에 별도 결정 정본을 만들지 않는다.

여러 흐름에 공통인 입력 방식·운영 시간 등은 한 번만 묻는다. 개인·기업의 수집 대상·열람 범위·보존 기간·외부 전송·추출 결과가 다르면 해당 차이만 추가 질문하고 별도 규칙으로 기록한다. 같은 회의에서 개인 할 일과 조직 후속 업무가 나오더라도 각 결과를 저장할 허용 영역을 따로 정한다.

| 시점·분기 | 사용자에게 확인할 내용 | 기록·진행 조건 |
| --- | --- | --- |
| 필요 선택 | “대화에서 무엇을 남기고 싶은가요? 검색 가능한 기록, 전체 전사, 짧은 요약, 지식 정리, 후속 할 일 중 필요한 것만 골라 주세요.” | D01 — 사용 / 제외 / 나중에와 원하는 결과 예시 |
| 입력 방식 선택 | “이미 있는 녹음·회의 전사·채팅 내보내기를 가져올까요, 앞으로 선택한 대화도 수집할까요?” | D02·D03 — 입력 한 가지부터 연결; 실시간 수집은 별도 선택 |
| 전체 보관 선택 | “선택한 대화의 음성·영상·채팅 원문까지 보관할까요, 전사·요약만 장기 보관할까요?” | D05 — 수집되는 원본과 장기 보관 대상을 구분 |
| 실제 자료 수집 전 | “어떤 대화·참여자·업무 범위가 대상이며, 수집 제외·일시 중지 조건은 무엇인가요?” | D04 — 기존 고지·허용 정책과 필요한 참여자 확인 절차 적용 |
| 실제 처리·저장 전 | “각 자료를 누가 보고 얼마나 보관하며, 외부 전사·모델 서비스로 보내도 되나요?” | D04·D05·D06 — 원본/전사/요약별 접근·보존·전송·비용 확인 |
| 후속 동작 설정 전 | “요약·할 일 후보까지만 만들까요, 정한 조건에서는 실제 업무 도구에도 반영할까요?” | D07·D09 — 자동 반영 범위·검증·확인 필요 조건 |

- 개인 사용자
	- 첫 시험은 원하는 대화 한 건으로 시작할 수 있다. 본인의 음성 메모, 강의, 허용된 인터뷰, 업무 회의, 선택한 채팅방은 여러 종류를 선택할 수 있으며 각각의 수집 범위를 정한다.
	- 같은 기기라도 개인·가족·고객·회사 대화를 구분한다. 회사 대화는 개인 녹음·저장 허용 범위로 간주하지 않는다.
	- 휴대폰에서 저장만 하고 집 컴퓨터가 켜졌을 때 전사하는 방식도 선택할 수 있다. 실제 사용하는 앱의 내보내기·로컬 보관·전송 지원 여부를 확인한다.
- 기업 사용자
	- 업무 책임자와 기존 회의·기록 정책을 확인하고, 팀·프로젝트·회의 종류별 수집 및 열람 범위를 정한다. 조직 전체 수집으로 확대하지 않는다.
	- 참가자에 외부인·고객이 포함될 때 적용할 고지·허용·제외 절차, 처리 위치와 자료 등급, 보존 책임자를 정한다. 법적 판단이 필요한 범위는 조직의 담당 정책으로 확정한다.
	- 참석 권한과 원본·전사·요약의 열람 권한을 각각 확인한다. 모든 참석자가 모든 파생 지식을 볼 수 있다고 가정하지 않는다.

질문 프롬프트 예시:

> 사용자가 선택한 대화 기능의 현재 단계에 필요한 질문만 최대 3개 한다. 기존 답변과 정책을 먼저 적용한다. 제품 이름보다 원하는 결과·대상 범위·실패 시 처리 예시를 묻는다. 답변으로 입력·저장·검증·반영 규칙을 작성하고, 의미가 추가되거나 충돌하는 부분만 확인한다. 선택하지 않은 실시간 녹음·영상·화자 식별·자동 후속 실행은 제외한다. 미응답을 수집·외부 전송·공유 허용으로 해석하지 않는다.

## 2. 필요한 역할과 제품 선택을 분리

| 역할 | 우선 재사용할 기능 | 부족한 경우에만 검토할 추가 구성 |
| --- | --- | --- |
| 수집 | 기존 녹음 파일, 허용된 회의 결과, 채팅 내보내기 | 선택한 회의의 자동 수집, 사용자가 켜는 녹음, 지원되는 연동 |
| 원본 보관 | 접근을 제한한 기존 폴더·문서/파일 저장소 | 대용량 파일 저장소·암호화·조직 보존 기능 |
| 전사 | 기존 서비스가 생성한 전사문 | 로컬 전사 또는 허용된 외부 전사 API |
| 정리·검색 | 기존 에이전트·Wiki·문서 검색 | 실제 검색 품질이 부족할 때 추가 색인·검색 도구 |
| 후속 업무 | 기존 할 일·캘린더·업무 시스템 | 지원되지 않는 동작에 대한 어댑터; 새 관리 앱은 필요할 때만 |
| 상태·복구 | 기존 실행기의 작업 기록과 파일 목록 | 중복·버전·복구를 기존 기능으로 처리할 수 없을 때 필요한 상태 저장 |

제품을 채택할 때에는 선택한 계정·플랜의 녹음/전사 권한, 지원 언어·화자·파일 크기/길이, 원본 내보내기, API 지원, 처리 지역·보존·삭제, 호출·저장 비용을 공식 자료와 실제 표본으로 확인한다. 앱 화면에서 전사문을 볼 수 있다는 사실만으로 API 수집이나 무료 자동 처리가 가능하다고 기록하지 않는다. 최초 설치와 연결은 [초기 셋업 흐름](<초기 셋업 흐름.md>)을 따른다.

## 3. 대화 한 건의 처리 흐름

### 3-1. 수집 범위 확인과 원본 접수

- 공통
	- 수집 전에 적용되는 범위·고지/허용 정책·중지 방법을 확인한다. 기존에 허용한 반복 수집은 그 조건 안에서 진행하고, 새 대화방·참가 범위·외부 전송 등 경계가 달라질 때만 필요한 결정을 추가한다.
	- 원본의 서비스·대화/회의/파일 ID, 수집 범위, 발생 시각·시간대, 수집 시각, 출처 링크·버전·접근 범위를 남긴다. 채팅은 필요한 메시지 ID·답글 연결·첨부 포함 여부를 보존하고 선택한 시간 범위를 표시한다.
	- 파일 수신 완료·열기 가능·크기/길이·수집 누락 여부를 확인한다. 일부만 수신한 파일이나 중간에 끊긴 녹음은 `부분 수집`으로 표시한다. 전체 대화를 확보했다고 표현하지 않는다.
	- 같은 권한 범위 안에서 원본 ID·버전·내용 해시 등으로 중복을 판별한다. 이름이 같은 다른 회의는 합치지 않고, 동일 입력의 재처리는 기존 결과를 대조한다.
- 개인 사용자
	- 하나의 지정 폴더나 선택한 대화 내보내기로 시작할 수 있다. 민감한 대화의 자동 동기화·자동 공유 여부를 확인한다.
- 기업 사용자
	- 실제 원본 접근 권한으로 수집한다. 팀별 권한을 유지하고, 공용 수집 계정으로 읽은 모든 내용을 모든 사용자의 검색 결과로 제공하지 않는다.

### 3-2. 원본과 전사문을 구분해 보존

- 원본은 선택한 보관 정책 안에서 보존하며 요약으로 덮어쓰지 않는다. 기존 원본 저장소를 정본으로 사용할 수 있고 무조건 복사본을 만들지 않는다. 장기 원본 보관을 선택하지 않았다면 처리 완료·복구에 필요한 임시 보관 기간과 삭제 시점을 정한다.
- 원본·전사문·요약·색인·후속 작업 사이에 출처와 버전의 연결을 남긴다. 나중에 특정 요약이나 할 일의 근거 대목을 찾을 수 있어야 한다. 별도 DB가 없어도 기존 파일의 메타데이터와 실행 기록으로 이 역할을 충족할 수 있다.
- 전사문에는 선택한 범위의 타임코드 또는 메시지 위치, 화자 구분, 언어, 전사 도구·버전, 누락·불명확 구간을 남긴다. 실제 이름을 확인할 수 없는 화자는 `화자 A` 등으로 두고 모델의 추측으로 이름을 확정하지 않는다. 음성으로 인물 신원을 추정하는 기능은 기본 범위가 아니다.
- 발음이 모호한 이름·숫자·일시·금액·부정 표현을 만들어 채우지 않는다. 전사 품질이 낮은 구간은 재청취·재전사 또는 확인 필요로 표시한다. 도구가 신뢰도 수치를 제공해도 정확성 보장으로 사용하지 않는다.
- 교정할 때 원본 파일과 최초 전사를 덮어쓰지 않고 교정본의 버전·교정자·대상 구간·이유를 기록한다. 재생성 결과가 기존 사용자 교정을 덮어쓰지 않도록 대조한다.

### 3-3. 요약·지식·할 일 후보 생성

| 결과 종류 | 담을 내용 | 확정으로 승격하지 않을 내용 |
| --- | --- | --- |
| 전사·대화 기록 | 원문과 위치·화자·누락 표시 | 모델이 보충한 말이나 추측한 화자 |
| 요약 | 논의 주제·결정·반대 의견·미해결점과 근거 | 의견의 차이를 합의로 바꾼 문장 |
| 지식 후보 | 출처·발언 주체·발생 시점·적용 범위·검증 상태 | 한 사람의 주장이나 농담을 일반 사실로 확정한 기억 |
| 할 일 후보 | 해야 할 일·담당·기한·근거·확인 필요 사항 | 희망·가정·제안이나 담당 불명 약속을 확정된 업무로 생성 |
| 일정 후보 | 실제 약속 여부·참석자·시간대·일시·근거 | “다음 주쯤” 등의 표현을 임의 시각으로 확정 |

대화 속 명령문·링크·첨부는 처리 대상 자료다. 녹음된 “이 파일을 지워”라는 말이나 채팅에 붙여 넣은 지시문이 에이전트의 도구 실행 권한을 부여하지 않는다. 대화 상대의 발언을 사용자의 지속 선호·마스터 규칙·스킬 변경으로 자동 승격하지 않는다.

확정된 발언 사실과 발언 내용의 진위를 구분한다. 예를 들어 “A가 납기가 금요일이라고 말했다”는 출처가 있는 발언 기록일 수 있지만, 실제 납기 확정 여부는 업무 시스템 또는 책임자 확인으로 검증한다. 기억에는 기록 시각과 내용이 유효한 시기를 구분하고, 이후 변경·철회 근거를 연결한다.

### 3-4. 검증 후 선택한 저장소·업무 도구에 반영

1. 전사·요약의 중요한 이름·숫자·일시·결정·담당자를 원본의 해당 구간과 대조한다. 분량·누락·언어 문제를 확인하고 확신이 없는 항목만 보류한다. 저위험 요약 전체를 매번 사람에게 승인받는 흐름을 기본값으로 만들지 않는다.
2. 지식 후보는 기존 지식·유효 시점·충돌·접근 범위를 대조하고, 정한 규칙을 통과한 내용만 반영한다. 미검증 후보는 확정 기억과 구분하여 검색·응답에 표시한다. 개인의 장기 선호·운영 규칙·스킬 변경에는 별도로 정한 변경 검증 절차를 적용한다.
3. 할 일·일정은 사용자 규칙이 허용하는 범위에서만 생성·변경한다. 후보 추출과 외부 시스템 쓰기를 분리하며, 담당·기한·대상 권한이 모호하면 후보로 남긴다. 이미 허용된 자동 등록은 중복·기존 상태·시간대 검증을 거쳐 실행한다.
4. 결과 ID와 실제 저장 내용을 다시 읽어 반영을 확인한다. 요약 전달 성공, 할 일 생성 성공, 실제 할 일 완료는 각각 기록한다. 전사문에 “완료했습니다”라는 말이 있어도 정한 완료 근거 없이 해당 업무를 완료 처리하지 않는다.
5. 정한 주기·중요도·조용한 시간 규칙에 따라 결과를 전달한다. 변경 없는 재처리·성공한 매 단계마다 새 알림을 보내지 않는다. 중요한 불확실성·수집 실패·후속 조치만 필요한 사람에게 알린다.

## 4. 저장·접근·보존·삭제 계약

아래는 선택한 대화 기능에 필요한 계약이다. 실제 값은 D04·D05·D07의 연결 계약에 채운다. `원본 장기 보관`과 `모든 자료 무기한 보관`은 다른 결정이다.

| 자료 | 정해야 할 내용 |
| --- | --- |
| 음성·영상·채팅 원본·첨부 | 정본 위치, 수집 범위, 열람 주체, 보관 기간, 암호화/백업, 재처리 가능 기간 |
| 최초 전사·교정본 | 원본 연결, 버전, 교정 권한, 화자·시각 표시, 보관 기간 |
| 요약·지식·검색 색인 | 근거 연결, 자료 등급·열람 권한, 갱신·충돌 처리, 보관 기간 |
| 할 일·일정·공유 결과 | 외부 결과 ID, 담당·접근 범위, 생성/변경/삭제 허용, 정정 방법 |
| 처리 로그·임시 파일·외부 서비스 사본 | 최소 메타데이터, 접근·보존, 임시 파일 삭제, 외부 삭제 지원·확인 방법 |

- 공통
	- 원본보다 넓은 범위로 요약·색인·모델 입력이 퍼지지 않도록 각각 접근·전송 정책을 적용한다. 요약이라는 이유만으로 공개 가능한 자료라고 간주하지 않는다.
	- 개인·기업 목표와 일정을 함께 조망하려면 허용된 바쁨/비어 있음 정보나 최소 메타데이터만 결합한다. 비공개 회의 내용·참여자·목표·대화 원문은 각 영역에 두고, 메타데이터도 반출이 허용된 범위만 사용한다.
	- 일반 운영 로그에는 대화 전체·음성 파일·민감 문장·토큰을 남기지 않는다. 작업 ID·단계·오류 코드·권한 있는 원본 참조 등 복구에 필요한 최소 정보만 기록한다.
	- 원본의 정정·삭제·접근 회수 시 영향받는 전사·요약·검색·기억·후속 작업을 연결 정보로 찾아 정한 정책을 적용한다. 원본만 지우고 검색 색인에 내용이 남는 상태를 완료로 표시하지 않는다.
	- 사용자가 수정한 후속 할 일을 근거 삭제만으로 무조건 삭제하지 않는다. 오래된 근거 표시·재검토·연결 해제·삭제 중 정한 처리와 실제 변경 범위를 적용한다.
	- 백업·외부 서비스·이미 전달된 사본의 삭제 범위와 지연·불가 항목을 구분해 기록한다. 확인하지 않은 완전 삭제를 보장하지 않는다. 복구 시 삭제·권한 회수 내역을 재적용해 자료가 되살아나지 않도록 한다.
- 개인 사용자
	- 보관 장소와 장치 분실·공유 링크·계정 해제 시 처리 방법을 본인이 이해할 수 있게 안내한다. 대화 원본을 다른 사람에게 공유하는 행동은 개인용 요약 생성과 별도 권한으로 다룬다.
- 기업 사용자
	- 조직의 보존·삭제·예외 보관 정책, 처리 지역, 외부 공급자 조건과 책임자를 적용한다. 자료 등급별 열람·다운로드·공유·반출을 구분하고 실제 접근 제한과 권한 회수 반영을 시험한다.

## 5. 실패·서버 중지·재개

`수집 완료 → 전사 대기 → 전사 완료 → 정리 완료 → 검증 완료 → 선택한 반영 완료`는 서로 다른 상태다. 도중 실패하면 성공한 결과와 남은 작업을 각각 남긴다. 이 상태 이름을 새 DB의 필수 스키마로 만들 필요는 없으며 기존 실행기의 단계 기록으로 충족할 수 있다.

| 상황 | 사용자에게 표시할 상태와 처리 |
| --- | --- |
| 파일 수신 실패·잘림 | 미수집/부분 수집; 원본 재수신·누락 범위 확인, 확보하지 못한 내용을 전사하지 않음 |
| 전사 오류·한도 소진 | 원본 접수 완료/전사 대기 또는 실패; 보관 정책 안에서 원본 유지, 예산·재시도 조건에 따라 재개 |
| 전사 성공·정리 실패 | 전사 완료/정리 대기; 성공한 전사를 재사용하고 불필요한 재전사 비용 방지 |
| 외부 할 일·일정 쓰기 결과 불명 | 정리 완료/반영 확인 필요; 기존 결과 ID·중복 키로 조회 후 처리, 무조건 다시 생성하지 않음 |
| 담당 서버 OFF | 해당 서버의 수집·전사·정리는 중지; 독립 실행 중인 휴대폰/회의 서비스의 저장 여부는 그 기능으로 별도 확인 |
| 서버 OFF 중 파일 업로드 | 지정 서비스에 파일이 저장된 사실과 에이전트 접수를 구분; 지원되는 수집 경로가 없으면 다음에 사용자가 파일을 전달 |
| 서버 ON으로 복귀 | 마지막 성공 단계·원본 보존 여부·유효한 권한·기존 결과를 대조 후 미완료 단계만 재개 |
| 수집 중 사용자가 중지 | 수집 중지 결과와 이미 수집된 자료의 처리/보관 여부를 구분해 정한 정책 적용 |

항상 켜진 수집 서버나 오프라인 큐가 필요하면 그 요구가 있을 때만 추가한다. 서버가 꺼진 동안 기기에서 대화가 자동 녹음되거나 외부 메시지가 무기한 보관된다고 가정하지 않는다. 기기·담당 호스트의 연속성은 [백엔드 설계](<백엔드·기기 연속성·비용 설계.md>)를 따른다.

## 6. 첫 실행과 대표 시나리오 검증

선택한 기능만 가상 또는 사용 허용된 짧은 표본으로 확인한다. 여러 시나리오를 선택했다면 공통 수집·전사 시험은 재사용하고, 각 시나리오의 출력·권한·후속 동작을 추가로 확인한다. 아래는 기대 동작이며 실제 통과 기록이 아니다. 근거·결과는 [검증·운영 기록](<../30_양식/검증·운영 기록.md>)에 남긴다.

- 개인 지식관리 — 강의/대화 한 건을 저장하고 질문으로 다시 찾기
	- 원본·전사·요약·Wiki 연결을 확인하고, 질문의 답변이 실제 대목을 가리키는지 확인한다. 이름이 틀린 전사를 교정했을 때 요약·검색 결과가 함께 갱신되어야 한다.
	- 원본과 사용자 교정은 보존 정책대로 유지하며 같은 파일 재수신으로 중복 노트가 생기지 않아야 한다.
- 개인 라이프 관리 — 대화에서 나온 후속 할 일을 주간 목표와 연결
	- “시간이 나면 해보자”는 후보로 남기고, 정한 담당·기한·허용 범위를 충족한 업무만 기존 할 일에 반영한다. 목표 연결이 불명확하면 임의의 목표를 만들지 않는다.
	- 알림 전달·사용자 확인·실제 수행 완료를 구분한다. 일정 시간이 지났거나 전사가 끝났다는 이유로 업무를 완료하지 않아야 한다.
- 기업 업무 — 회의 결과를 권한 안에서 지식·후속 업무로 반영
	- 소속·역할이 다른 시험 사용자로 원본·요약·검색 결과의 권한을 확인하고, 업무 책임자·기한이 모호한 항목은 필요한 확인으로 남겨야 한다.
	- 원본 접근을 회수했을 때 검색·요약·기억의 접근이 함께 제한되는지 확인한다. 기존 조직 절차에 따른 검토가 필요한 외부 공유·업무 변경은 해당 단계에서만 적용한다.
- 공통 실패·정정
	- 화자 불명·부정 표현·숫자 오류·중간 누락 표본에서 추측으로 빈칸을 채우지 않아야 한다. 전사 성공은 내용 정확성 검증과 별도다.
	- 전사 실패 후 원본으로 재개하고, 이미 생성된 할 일은 중복 생성하지 않아야 한다. 원본 보관이 끝났다면 재전사 불가 상태와 대체 방법을 표시한다.
	- 대화 속 도구 실행 지시를 자료로 다루고, 원본 정정·삭제 시 파생 자료 처리 결과와 남은 예외를 확인한다.

운영 인수 시 사용자는 수집 시작·중지, 처리 상태 보기, 원문 대목 확인, 화자·전사 교정, 후보 채택·거절, 정정·삭제 요청 방법을 알아야 한다. 구현하지 않은 동작은 지원한다고 안내하지 않고 현재 사용 가능한 경로와 남은 작업을 적는다.
