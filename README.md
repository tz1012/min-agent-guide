# 최소한의 에이전트 시스템 구축 — 안내 사이트

Obsidian 구축 패키지를 바탕으로 공개 구축본과 정적 안내 사이트를 제공합니다. 사이트는 `index.html`과 `vercel.json`으로 동작하며 빌드나 별도 데이터베이스가 필요하지 않습니다. 실제 시스템은 공개 문서를 받은 에이전트가 사용자의 대상 환경에서 구축합니다.

- 사이트 내용: `index.html`의 본문과 `STEPS`, `FLOW`, `WHERE`, `SV`, `D`, `T`, `F`, `S` 배열
- 공개 세부 가이드: [Sheets·Drive 전체 DB 설계](docs/google-workspace-db.md)
- 공개 구축 폴더: [guide/README.md](guide/README.md) · [구축 원칙](guide/AGENTS.md)
- 웹으로 읽는 에이전트 진입점: [start.md](start.md) · [짧은 자료 목록](llms.txt)
- 다운로드: [구축 폴더 ZIP](downloads/min-agent-guide.zip) — 압축 해제 후 `guide/` 폴더를 엽니다.
- 운영 사이트: [min-agent-guide.vercel.app](https://min-agent-guide.vercel.app/)
- 기준 문서: Obsidian `100_Projects/130_Creative/Active/최소한의 에이전트 시스템 구축/`
- 개정 기준 커밋: `23fd7e026f1110fe048d49a1503bcc91d22fb7ae` (`main`, 2026-10-28)

`guide/`는 설계·설치·운영 절차, 빈 기록 양식, 공식 참고와 가상 검증 자료를 포함하는 공개 구축본입니다. 개인 원문·원본 목록·실제 운영 계정과 시트 정보·비공개 유지보수 기록을 제외했으며, 필요한 지침과 연결 문서는 공개 폴더 안에서 따라갈 수 있게 구성합니다. README 한 개만 받은 에이전트가 폴더 전체를 확보했다고 가정해서는 안 됩니다.

## 에이전트로 시작하기

1. 사이트 주소로 시작하면 [에이전트용 시작 안내](https://min-agent-guide.vercel.app/start.md)에서 자료 경로를 확인합니다. ZIP을 풀어 `guide/`를 작업 공간으로 열거나, 에이전트가 이 저장소에서 `guide/` 전체를 확보하게 합니다.
2. 실제 설치 대상에 접근할 수 있는 Codex·Claude·Hermes 등의 에이전트에게 사이트의 **에이전트 시작 문구 복사** 버튼으로 얻은 문구를 보냅니다.
3. `guide/README.md → guide/AGENTS.md → 셋업 진행 기록과 필요한 연결 문서` 순서로 읽고, 실제 환경을 확인합니다. `guide/`가 작업 공간 루트라면 그 안의 README와 AGENTS부터 읽습니다.
4. 필요한 질문에 답해 전체 구조·권한·비용·첫 업무를 정한 뒤 허용된 구축·검증을 진행합니다. 진행 기록이 있으면 실제 상태를 대조하고 미완료 단계부터 이어갑니다.

웹 읽기만 가능한 에이전트는 설계·명령·진행 기록을 준비합니다. 대상 환경의 설치·인증·파일 작업은 실행 가능한 에이전트에 이어서 맡기거나 안내된 사용자 작업으로 진행합니다. 사이트 접속이나 ZIP 다운로드 자체가 PC에 시스템을 설치하지는 않습니다.

## 구축하면 할 수 있는 일

**내 자료를 기억하고, 내 할 일을 챙기고, 내 업무를 이어가는 AI.**

- 저장한 자료에서 근거를 찾아 출처가 있는 답과 초안을 받습니다.
- 목표와 일정을 연결해 오늘 할 일과 시간 배치를 정리합니다.
- 허용된 회의·대화를 결정 사항과 후속 업무로 연결합니다.
- 개인·기업의 반복 업무를 정한 권한과 확인 절차에 따라 이어 처리합니다.

하나부터 시작하거나 여러 흐름을 함께 선택할 수 있습니다. 실제 가능한 일은 연결한 자료·서비스·규칙·실행 환경에 따라 정하며, 이 사이트는 그 시스템을 만드는 안내입니다.

## 세 곳의 내용 갱신

현재 Obsidian·GitHub·Vercel 사이의 자동 콘텐츠 동기화는 구현되어 있지 않습니다. 변경할 때 아래 순서로 반영하고 각 단계의 완료 여부를 구분합니다.

1. **Obsidian 정본 수정:** 기능 정의와 설계·결정·검증 양식의 연결 및 개인/기업 조건을 확인합니다.
2. **공개본 선별 반영:** 변경된 역할·질문·예시·검증 기준을 HTML·`guide/`·공개 세부 가이드에 옮기고 ZIP을 다시 만듭니다. 개인 원본을 복제하지 않고 익명화한 스키마와 가상 사례를 사용합니다.
3. **로컬 확인:** HTML·JavaScript·JSON, 공개 폴더의 링크·ZIP 내용, 복수 흐름 선택·서버 ON/OFF·도구 탭·복사·체크·다운로드 동작을 확인합니다. 체크 상태는 해당 브라우저의 localStorage에만 저장되며 실제 구축·검증 상태가 아닙니다.
4. **GitHub 반영:** 변경 범위를 검토하고 허용된 분기에 커밋·push합니다. 반영한 Obsidian 문서·공개 파일·커밋을 작업 기록에 남깁니다. 로컬 편집 완료와 원격 반영 완료를 구분합니다.
5. **Vercel 확인:** 올바른 프로젝트·계정·연결 저장소·분기·실제 사이트 URL을 확인합니다. Git 연동 여부와 배포 결과를 확인하고, 게시된 페이지에서 해당 변경과 주요 동작을 다시 검증합니다. GitHub push 성공만으로 사이트 배포 완료를 보고하지 않습니다.

운영 사이트는 `https://min-agent-guide.vercel.app/`, 기존 프로젝트는 `min-agent-guide`입니다. 2026-10-28 확인한 최초 배포는 직접 업로드 방식이며 Git 자동 연결 정보는 없었습니다. 이번 변경 이후에도 배포별 커밋·실제 주소·검증 결과를 따로 확인합니다. 동일 이름의 새 프로젝트를 만들거나 GitHub 반영만으로 자동 배포를 가정하지 않습니다. 최초 Import가 필요한 경우의 설정은 Framework Preset `Other`, 빌드 설정 비움이며, 기존 프로젝트가 있으면 그 설정을 먼저 확인합니다.

## 공개 범위

- 공개 가능: 일반화된 설계, 빈 양식, 익명 스키마, 가상 예시, 공식 참고 링크.
- 제외: 실제 Google 시트/Drive 파일 이름·ID·URL·내용, 개인 대화·전사, 계정·공유자 정보, 토큰·키, 개인 경로와 운영 로그.
- Obsidian의 `90_참고자료/원본/`·원본 목록·비공개 유지보수 기록을 공개 폴더와 ZIP에 넣지 않습니다. 공개 인용이 필요한 내용은 출처·공개 가능 범위를 개별 확인합니다.
- 공개본과 정본이 다르면 범위와 이유를 기록합니다. 사이트의 요약이 기능 정의나 실제 사용자 결정·권한을 대신하지 않습니다.

## 로컬 점검

공개 `guide/` 문서를 수정한 뒤 `python scripts/package-guide.py`를 실행하면 내부 링크를 확인하고 파일별 SHA-256 매니페스트와 ZIP을 다시 만듭니다. 개인 원본을 공개 문서로 자동 변환하는 스크립트는 아니므로, 공개 범위 검토는 먼저 진행합니다. 사용자별로 채운 운영 기록은 사용자의 작업 공간에서 관리합니다.

```sh
python -m http.server 8000 --bind 127.0.0.1
```

`http://127.0.0.1:8000/`에서 데스크톱·모바일 폭, 복수 시나리오, 데이터베이스 비교, 서버 ON/OFF, D01–D09 체크, 도구 탭, 문구 복사, 공개 구축 폴더·세부 가이드 링크와 ZIP 다운로드를 확인합니다. 이 명령은 로컬 미리보기이며 Vercel 배포가 아닙니다.

실제 에이전트 설치·서비스 연결·운영 검증은 미수행입니다. 사이트 개정과 해당 에이전트 시스템의 구축 완료를 구분합니다.

공개 상세 문서는 원본 `10_구축/Google 도구 기반 최소 구성.md`에서 개인 식별자를 제외한 설계 설명을 옮긴 것입니다. 비공개 패키지 안의 상대 링크는 공개본에서 일반 문서 이름으로 바꾸었습니다.
