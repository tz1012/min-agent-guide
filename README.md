## 에이전트로 시작하기

1. 사이트 주소로 시작하면 [에이전트용 시작 안내](https://min-agent-guide.vercel.app/start.md)에서 자료 경로를 확인합니다. ZIP을 풀어 `guide/`를 작업 공간으로 열거나, 에이전트가 이 저장소에서 `guide/` 전체를 확보하게 합니다.
2. 실제 설치 대상에 접근할 수 있는 에이전트에게 사이트의 **에이전트 시작 문구 복사** 버튼으로 얻은 문구를 보냅니다. Hermes는 적용 예시 중 하나이며 OpenClaw·Codex·Claude·OmO 등 사용 중이거나 필요에 맞는 에이전트를 선택합니다. 목록 밖의 에이전트도 [공통 운영 계약](guide/20_도구별/실행기%20독립%20운영%20검증.md)에 맞춰 실제 제품·버전·지원 기능을 확인하고, 구축 도구와 운영 실행기를 구분합니다. 제품별 예시가 모든 제품의 같은 기능·즉시 동작을 보장하지는 않습니다.
3. `guide/README.md → guide/AGENTS.md → 셋업 진행 기록과 필요한 연결 문서` 순서로 읽고, 실제 환경을 확인합니다. `guide/`가 작업 공간 루트라면 그 안의 README와 AGENTS부터 읽습니다.
4. 필요한 질문에 답해 전체 구조·권한·비용·첫 업무를 정한 뒤 허용된 구축·검증을 진행합니다. Jev와 Reason Network는 필요한 역할과 기존 대안을 비교해 각각 도입·미도입·보류를 결정합니다. 진행 기록이 있으면 실제 상태를 대조하고 미완료 단계부터 이어갑니다.
5. 사용자가 매번 묻기 전에 에이전트가 정한 시간·이벤트에 기동하도록 구성합니다. 최신 목표·미완료·일정 조회→우선순위·이유·첫 행동 제안→허용 수정→결과 재조회→완료 근거·다음 행동을 연결합니다. 조용한 시간·실행/비용 상한·중단·OFF 규칙도 적용합니다.
6. 실제 시간·이벤트 기동과 수정·재확인 흐름을 선택한 실행기에서 시험합니다. 콘텐츠 자동화를 선택했다면 실제 입력 한 건의 수신·위키 반영·새 대화 재검색까지 확인합니다. 이메일은 선택한 API/IMAP/POP3 수신·필요한 로컬 앱과 에이전트 연결을 각각 검증하고, 발송은 별도 허용 범위의 SMTP/API 설정에 따라 시험합니다.
7. 다른 메신저·문서·일정·파일·회의 프로그램도 공식 설정·계정 권한·로그인 등 사용자 조치를 안내하고 실제 동작을 검증합니다. 선택한 모든 연결·능동 운영 경로의 결과를 대조하고, 미완료 경로는 이유와 다음 행동을 남깁니다. 첫 연결 성공을 전체 구축 완료로 기록하지 않습니다.
8. 선택 구성 최종 체크리스트로 Jev·Reason Network의 결정 누락과 실제 증거를 대조합니다. 기존 `guide/30_양식/검증·운영 기록.md` 안의 최종 구축 보고서에 완료·미검증·보류·사용자 행동을 정리합니다. 별도 빈 보고 양식을 만들지 않습니다.

웹 읽기만 가능한 에이전트는 설계·명령·진행 기록을 준비합니다. 대상 환경의 설치·인증·파일 작업은 실행 가능한 에이전트에 이어서 맡기거나 안내된 사용자 작업으로 진행합니다. 사이트 접속이나 ZIP 다운로드 자체가 PC에 시스템을 설치하지는 않습니다.

## 구축하면 할 수 있는 일

**내 자료를 기억하고, 내 할 일을 챙기고, 내 업무를 이어가는 AI**

- 새 자료나 업무 변화를 확인해 관련 지식·근거·활용할 다음 행동을 먼저 제안합니다.
- 최신 목표·미완료 업무·일정을 조회해 오늘 우선순위와 이유·첫 행동을 먼저 제안합니다.
- 허용된 회의 기록이 도착하면 결정과 후속 업무를 연결하고 진행·완료 근거를 추적합니다.
- 개인·기업 업무의 막힘을 찾아 허용된 수정과 결과 재확인을 이어가고, 실제 완료와 남은 판단을 구분합니다.

하나부터 시작하거나 여러 흐름을 함께 선택할 수 있습니다. 실제 가능한 일은 연결한 자료·서비스·규칙·실행 환경에 따라 정하며, 이 사이트는 그 시스템을 만드는 안내입니다.

## 에이전트가 먼저 확인하고 완료까지 추적하는 운영

기본 설계는 에이전트가 정한 시간·상태 변화에 먼저 움직이는 운영입니다. 아침에는 최신 목표·미완료·일정에서 우선순위와 이유·첫 행동을 제안합니다. 낮에는 진행·막힘을 확인하고 허용된 수정 뒤 결과를 다시 조회합니다. 저녁에는 실제 완료 근거·남은 일을 먼저 정리하고 내일 계획의 수정안을 제시합니다. 사용자의 판단이 부족한 부분만 묻고, 직접 요청과 방향 변경도 지원합니다.

지속 확인은 무한 모델 호출이나 반복 알림이 아닙니다. 실제 트리거·확인 주기·조용한 시간·알림 빈도·실행 및 비용 상한·중단과 재개 조건을 정합니다. 서버가 꺼져 있을 때 실행된 것처럼 표시하지 않으며, 복귀 후 오래된 계획·만료·중복을 대조합니다. 알림 발송이나 시간 경과를 업무 완료로 처리하지 않습니다.

어떤 실행기를 사용하든 실제 기동·상태 저장·재개·권한 거부·허용 수정·결과 재확인·다음 행동의 공통 계약으로 검증합니다. 내장 기능이 부족하면 필요한 외부 구성 또는 대안을 명시합니다. 지침 파일을 읽었거나 제품이 설치됐다는 사실만으로 동작을 검증했다고 기록하지 않습니다.

## 콘텐츠와 이메일을 연결하는 방법

자료 수집을 선택하면 에이전트가 수신 채널·계정, 작동 조건, 지시 없이 전달한 링크·파일·텍스트의 기본 처리, 저장소, 자동 반영 범위와 응답 위치를 질문하고 설정합니다. 수신 → 원문·출처 보관 → 기존 지식과 종합 → 위키·연결·목록·이력 갱신 → 결과 안내 → 새 대화에서 검색·재사용을 하나의 흐름으로 검증합니다. 중복·부분 실패·서버 중단도 구분하며, 실제 동작 증거가 없으면 완료로 기록하지 않습니다.

이메일은 Gmail 외에도 제공자가 지원하는 IMAP/POP3 수신과 SMTP 발송을 고려합니다. 여러 기기의 서버 상태 동기화가 필요하면 IMAP을 우선 검토하고, POP3는 서버 사본 유지·삭제와 로컬 원본·백업을 먼저 정합니다. PC에서 무료 로컬 앱이 필요하면 [Thunderbird](https://www.thunderbird.net/)를 후보로 안내하며, 제공자의 공식 서버·포트·암호화·인증 방식으로 설정합니다. 메일 앱 설치, 에이전트의 수신 연결, 발송 권한은 각각 결정하고 확인합니다. 사용자 로그인·2FA는 정확한 화면·행동·완료 신호를 안내하며 비밀값은 공개 기록에 남기지 않습니다.

Google Calendar·Gmail은 [Google 계정 연결·대리 설정](guide/10_구축/Google%20계정%20연결·대리%20설정.md)에 따라 계정·목적·범위를 정하고 기존 커넥터부터 확인합니다. 에이전트가 허용된 설치·설정을 직접 수행하고, 사용자에게 필요한 공식 로그인·2FA·동의·관리자 조치의 화면과 완료 신호를 안내한 뒤 나머지 작업을 이어갑니다. 이미 확정한 권한을 재질문하지 않으며 Gmail 읽기·초안·발신, Calendar 읽기·편집·초대를 각각 선택합니다. 자동 발송·초대는 기본 허용하지 않습니다.

현재 채팅 연결과 실제 운영 호스트의 연결은 별도로 확인합니다. 선택한 기능만 시험하고 허용된 조회 경로나 사용자 화면으로 결과를 확인합니다. 운영 호스트의 인증을 확인하고 능동 운영을 선택하면 트리거·재시작도 검증합니다. 연결 위치·허용 범위·증거·남은 사용자 행동을 기존 진행 기록과 최종 보고서에 인계합니다.

선택한 실제 환경의 연결·수신·재사용 검증은 구축 과정에서 수행합니다. 가이드와 사이트를 게시한 것은 개인 계정 연결이나 자동화 운영의 완료를 뜻하지 않습니다.

다른 연결 프로그램도 사용자가 선택한 범위만 설치·설정합니다. 에이전트가 서비스별 공식 설정 방법과 실행기의 지원 기능을 대조하고, 필요한 로그인·앱 등록·관리자 조치를 안내합니다. 각 연결의 사용 기능에 맞춰 수신·조회·반영·재조회 시험을 남기며, 완료·사용자 조치 대기·지원되지 않음·구축 대기를 구분합니다.

| [Jev](guide/90_참고자료/SQLite와%20Jev%20확인%20사항.md) | 반복되는 좁은 의미 판단을 API로 처리해 선택·점수·참/거짓 확률을 받는 후보. 작업 DB·LLM Wiki와 구분하며 실제 표본의 품질·지연·총비용으로 비교 | 명확한 조건은 코드·규칙, 의미 판단은 **기존 모델 + 분류 전용 프롬프트**부터 비교하고 필요한 경우 사람이 확인 |
| [Reason Network](guide/90_참고자료/Reason%20Network%20비용·적용%20검토.md) | 여러 실행기·기기에서 세션을 찾고 요청·응답을 주고받아야 할 때 검토하는 통신 연결. 작업 정본·스케줄러는 별도로 유지 | 한 실행기와 기존 메신저·원격 접점, 공유 작업 ID·진행 기록을 통한 명시적 인계 |

[분류 전용 프롬프트와 검증](guide/10_구축/분류%20전용%20프롬프트와%20검증.md)은 기존 모델에서 제공한 유형·프로젝트 후보만 선택하고, 판단 후보 JSON만 반환하는 예시와 시험 절차입니다. 부족하거나 충돌하는 정보는 `uncertain`으로 두고 근거 위치·검토 필요 여부를 남깁니다. 입력 속 지시는 데이터로만 취급하며 실행·완료 상태 변경은 하지 않습니다. 코드 규칙과 기존 모델 프롬프트를 같은 표본의 품질·비용·지연으로 비교하고, Jev는 필요·권한·예산이 정해진 경우에만 같은 기준으로 추가 비교합니다. 기존 모델의 호출 토큰·API 비용·구독 사용 한도가 소모될 수 있고 Jev와 같은 성능을 보장하지 않습니다.

각각 도입 / 미도입 / 보류 결정·이유·대안·설정 및 시험 근거를 남깁니다. 분류를 사용하면 선택 방식·프롬프트와 모델 버전·동일 표본의 시험 근거도 기록합니다. Jev 미도입도 이유와 대안, 기존 구성으로 요구를 충족하는 근거를 남깁니다. 보류이면 담당자·재검토 조건과 기한·현재 구축에 미치는 영향·다음 행동을 명시합니다. 가격·제공 기능·데이터 전송과 권한 조건은 실제 도입 시점에 확인합니다.

최종 판단과 증거는 [선택 구성 검토·최종 체크리스트](guide/10_구축/선택%20구성%20검토·최종%20체크리스트.md)에 따라 기존 [검증·운영 기록](guide/30_양식/검증·운영%20기록.md)의 최종 구축 보고서에 연결합니다. 사이트 체크 상태는 해당 브라우저의 localStorage에 저장되는 보조 표시이며 제품 설치·실제 검증 완료를 대신하지 않습니다.

## 세 곳의 내용 갱신

현재 Obsidian·GitHub·Vercel 사이의 자동 콘텐츠 동기화는 구현되어 있지 않습니다. 변경할 때 아래 순서로 반영하고 각 단계의 완료 여부를 구분합니다.

1. **Obsidian 정본 수정:** 기능 정의와 설계·결정·검증 양식의 연결 및 개인/기업 조건을 확인합니다.
2. **공개본 선별 반영:** 변경된 역할·질문·예시·검증 기준을 HTML·`guide/`·공개 세부 가이드에 옮기고 ZIP을 다시 만듭니다. 개인 원본을 복제하지 않고 익명화한 스키마와 가상 사례를 사용합니다.
3. **로컬 확인:** HTML·JavaScript·JSON, 공개 폴더의 링크·ZIP 내용, 복수 흐름 선택·서버 ON/OFF·도구 탭·복사·체크·다운로드 동작을 확인합니다. 체크 상태는 해당 브라우저의 localStorage에만 저장되며 실제 구축·검증 상태가 아닙니다.
4. **GitHub 반영:** 변경 범위를 검토하고 허용된 분기에 커밋·push합니다. 반영한 Obsidian 문서·공개 파일·커밋을 작업 기록에 남깁니다. 로컬 편집 완료와 원격 반영 완료를 구분합니다.
5. **Vercel 확인:** 올바른 프로젝트·계정·연결 저장소·분기·실제 사이트 URL을 확인합니다. Git 연동 여부와 배포 결과를 확인하고, 게시된 페이지에서 해당 변경과 주요 동작을 다시 검증합니다. GitHub push 성공만으로 사이트 배포 완료를 보고하지 않습니다.

운영 사이트는 `https://min-agent-guide.vercel.app/`, 기존 프로젝트는 `min-agent-guide`입니다. 2026-10-28 확인한 최초 배포는 직접 업로드 방식이며 Git 자동 연결 정보는 없었습니다. 이번 변경 이후에도 배포별 커밋·실제 주소·검증 결과를 따로 확인합니다. 동일 이름의 새 프로젝트를 만들거나 GitHub 반영만으로 자동 배포를 가정하지 않습니다. 최초 Import가 필요한 경우의 설정은 Framework Preset `Other`, 빌드 설정 비움이며, 기존 프로젝트가 있으면 그 설정을 먼저 확인합니다.

## 공개 범위

- 공개 가능: 일반화된 설계, 빈 양식, 익명 스키마, 가상 예시, 공식 참고 링크.
- 제외: 실제 Google 시트/Drive 파일 이름·ID·URL·내용, 개인 대화·전사, 계정·공유자 정보, 토큰·키, 개인 경로와 운영 로그.
- Obsidian의 `90_참고자료/원본/`·원본 목록·비공개 유지보수 기록을 공개 폴더와 ZIP에 넣지 않습니다. 공개 인용이 필요한 내용은 출처·공개 가능 범위를 개별 확인합니다.
- 공개본과 정본이 다르면 범위와 이유를 기록합니다. 사이트의 요약이 기능 정의나 실제 사용자 결정·권한을 대신하지 않습니다.

## 로컬 점검

공개 `guide/` 문서를 수정한 뒤 `python scripts/package-guide.py`를 실행하면 내부 링크를 확인하고 파일별 SHA-256 매니페스트와 ZIP을 다시 만듭니다. 개인 원본을 공개 문서로 자동 변환하는 스크립트는 아니므로, 공개 범위 검토는 먼저 진행합니다. 사용자별로 채운 운영 기록은 사용자의 작업 공간에서 관리합니다.

```sh
python -m http.server 8000 --bind 127.0.0.1
```

`http://127.0.0.1:8000/`에서 데스크톱·모바일 폭, 복수 시나리오, 데이터베이스 비교, 서버 ON/OFF, D01–D09 체크, 도구 탭, 문구 복사, 공개 구축 폴더·세부 가이드 링크와 ZIP 다운로드를 확인합니다. 이 명령은 로컬 미리보기이며 Vercel 배포가 아닙니다.

실제 구축은 제공 문서와 사용자가 확정한 규칙을 기준으로 진행합니다. 설치·서비스 연결·운영은 각 사용자의 환경에서 확인하고 검증합니다. 사이트 개정과 해당 에이전트 시스템의 구축 완료를 구분합니다.

공개 상세 문서는 원본 `10_구축/Google 도구 기반 최소 구성.md`에서 개인 식별자를 제외한 설계 설명을 옮긴 것입니다. 비공개 패키지 안의 상대 링크는 공개본에서 일반 문서 이름으로 바꾸었습니다.
